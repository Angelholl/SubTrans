- 布局族：`.form-card`:1533（`flex-wrap:wrap; gap:var(--space-3); align-items:center`）、`.action-row`:1491、`.field-row`:1477（`gap:var(--space-4)`=16px、`flex-wrap:wrap`）、`.field-col`:1484、`.inline-field`:1464、`.field-label`:1457、`.path-row`:1507、`.path-row-label`:1515（`font-weight:600`）、`.field-btn-row`:1523、` .stage-row`:1571、`.alt-row`:1590、`.stack`:1498 / `.stack.form-card{align-items:stretch}`:1546。

### 1.3 「框过长」的根因（必须写进实现卡，否则会被当单点修）

`.workbench.aside-collapsed`（`:203-205`）把右栏由 316px 收成 44px，**主区净增 272px**。所有 `.grow` 元素（`flex:1`，`:1504`）因此等比拉伸：

- `#refineS1Endpoint` / `#refineS3Endpoint`（`class="form-input compact grow"`）→ 1920 窗折叠态下输入框 ≈ **1300px+**；
- `label.path-row.grow` 的目录框同样吃掉全部余量。

即：**「框过长」不是宽度值写错了，是弹性分配没有上限**。所有收敛方案的共同解法是给 `grow` 加 `flex-basis` + `max-width`，而不是改死 `width`。

### 1.4 「错落」的根因

- 兜底容错卡 `.form-card` 是 `align-items:center`（`:1536`）。档位/上下文两列被 `:has()` 强制成「顶置标签+控件」两行结构（约 19+4+30 ≈ 53px），目录 `label.path-row` 同样被 `:has(> .form-input)` 强制成列排（标签/输入/按钮 三层，约 19+4+30+4+30 ≈ 87px）。两者高度不同且垂直居中 → **顶部标签线错位约 17px**，这正是 owner 说的「三列与整行框混排视觉杂」。
- 兜底并发卡 `.field-row` `gap:var(--space-4)`（16px）均匀铺开 5 个控件，控件语义（兜底/批量/并发）无分组，末位「并行」因余量不足被挤到第二行且贴左 → 「拥挤+错落」。

## 2. 阶段A/B 地址行（框宽策略）

### 现状

```html
<!-- index.html:263-269（阶段A；阶段B :307-312 同构） -->
<div class="action-row">
  <label class="field-label" style="min-width:var(--w-endpoint-label);">阶段A 地址</label>
  <input id="refineS1Endpoint" class="form-input compact grow" ...>
  <button id="refineSaveEndpointsBtn" class="btn btn-primary btn-compact">…保存接口</button>
  <span id="refineEndpointStatus" class="muted"></span>
</div>
```

三个问题：① `grow` 无上限（§1.3）；② 地址行是 `.form-card` 的**兄弟**（在 `.stage-group` 内），没有卡面/描边/内边距，视觉上像一条从卡上掉下来的散条；③ 状态 span 无 `nowrap`/无 `min-width:0`，长状态文本会把整行撑乱。

### 甲案（推荐）：地址行并回卡内 + 输入框限宽

**结构**：把 `.action-row` 移入同段 `.form-card` 末尾，作为该卡的第三行（`stage-row` / `alt-row` / `endpoint-row` 三行同卡），label 换成 `.path-row-label` 同款口径。

**CSS（`style.css` 建议新增）**：

```css
/* 阶段地址行（并卡内第三行；--w-endpoint-input 见 §5 token 增补） */
.form-card > .endpoint-row {
    flex: 1 1 100%;          /* 独占一行，与上两行同卡面 */
    min-width: 0;
    gap: var(--space-2);
    align-items: center;
    flex-wrap: wrap;
}
.form-card > .endpoint-row > .field-label { flex: none; }   /* 替掉 index.html:264 内联 min-width */
.form-card > .endpoint-row > .form-input {
    flex: 1 1 var(--w-endpoint-input);
    max-width: var(--w-endpoint-input);
    min-width: 0;
}
.form-card > .endpoint-row > .btn-compact { flex: 0 0 auto; }
/* 状态文本：同行优先，放不下时整行成行（复用 .stage-row .muted 先例，:1581-1588） */
.form-card > .endpoint-row > .muted {
    flex: 1 1 auto;
    min-width: 0;
    overflow-wrap: anywhere;
}
@media (max-width: 1180px) {
    .form-card > .endpoint-row > .form-input { flex-basis: 100%; max-width: 100%; }
}
```

**建议同时删掉** `index.html:264/:308` 的 `style="min-width:var(--w-endpoint-label);"`（收编为类规则，与钉①的收编精神一致；注意切片锚不含地址行，删内联不触发钉①，但**注释锚不得动**，见 §6）。

### 乙案（最小改动·仅当评议否决并卡）：保持卡外，只做视觉收敛 + 限宽

```css
.endpoint-row {                      /* 给 index.html:263/:307 的 .action-row 加 class，零 id */
    gap: var(--space-2);
    align-items: center;
}
.endpoint-row > .form-input {
    flex: 1 1 var(--w-endpoint-input);
    max-width: var(--w-endpoint-input);
    min-width: 0;
}
```

甲案 vs 乙案取舍：

| 维度 | 甲案（并卡内） | 乙案（卡外限宽） |
| --- | --- | --- |
| 视觉完整度 | 高：三行同卡面，与 API Key 行同宽对齐 | 中：仍是卡外散条，但框不再过长 |
| DOM 改动 | 移动 2 个节点（零 id 变更） | 加 2 个 class |
| 窄窗表现 | 走 `.form-card` 既有 wrap | 需自备 wrap |
| 回归面 | 触及 `test_ui_phase3_redlines.py:35` 切片锚之外的区域，但建议同步审注释锚 | 最小 |

**渲染变化**：1920 折叠态下地址输入框 ≈ 1300px → 440px；「保存接口」钮从卡片最右端收回到输入框右侧约 60px 处，形成稳定的「左起标签—输入—动作」节奏。控件高 36px 不变，行高不变。

## 3. 兜底与容错卡（三列与目录长框的分组）

### 甲案（推荐·同构三列 + 目录列两行）

**分组原则**：三个字段统一为「顶置标签 + 控件」列；目录列在列内再分两行（标签行 / 输入框+浏览+打开 行），使全卡三列等高、顶部标签线齐平，彻底消除「三列 + 整行框」的混排。

**结构（最小差量）**：
1. `:318` 的 `.form-card` 加 class `fallback-card`（零 id）；
2. `:335` 的 `label.path-row.grow` 内，把 `#refineCleanerConfigShow` 与 `.field-btn-row` 包进一个 `<span class="dir-input-line">`（`label` 的内容模型是 phrasing content，**必须用 span，不能用 div**）；`#refineCleanerConfig`（hidden 载体）与 `.path-row-label` 留在 label 直接子级。

```html
<label class="path-row grow">
  <span class="path-row-label" data-i18n="cleaner_dir_label">净语配置目录</span>
  <input type="hidden" id="refineCleanerConfig">
  <span class="dir-input-line">
    <input id="refineCleanerConfigShow" class="form-input compact grow" readonly ...>
    <span class="field-btn-row">…浏览... / 打开…</span>
  </span>
</label>
```

**CSS（放在 `style.css` :1569 之后，依赖更高特异性压过 `:has()` 强制）**：

```css
/* 兜底与容错卡：三列同构收敛（追记 D2026-1013-01） */
.form-card.fallback-card { align-items: flex-start; }              /* 顶部标签线齐平 */
.form-card.fallback-card > label.inline-field { flex: 0 0 auto; }  /* 前两列内容宽 */
/* 中和 :1558-1569 的 width:100%!important，交回 --w-profile/--w-ctx 生效 */
.form-card.fallback-card > label.inline-field > .form-select,
.form-card.fallback-card > label.inline-field > .form-input { width: auto !important; }
/* 第三列：吃掉余量，但输入框本体限宽，钮右对齐 */
.form-card.fallback-card > .path-row { flex: 1 1 320px; min-width: 0; }
.form-card.fallback-card > .path-row > .form-input {
    width: auto !important;
    flex: 1 1 var(--w-cleaner-input);
    max-width: var(--w-cleaner-input);
}
.dir-input-line {
    display: flex;
    align-items: center;
    gap: var(--space-2);
    min-width: 0;
    flex: 1 1 auto;
}
.form-card.fallback-card .field-btn-row { margin-left: auto; }   /* 动作贴卡右缘 */
```

**特异性核算**（落地者必须复核，`:has()` 侧带 `!important`）：
- `.form-card:not(.stack) label > .form-input` = `(0,3,1)`；
- `.form-card.fallback-card > label.inline-field > .form-input` = `(0,4,1)` ✔；
- `.form-card.fallback-card > .path-row > .form-input` = `(0,4,0)` ✔（类数 4 > 3）；
- `.form-card.fallback-card > .path-row`（不加 `!important`）=`(0,3,0)`，可安全覆盖 `.path-row` 的 `flex-wrap:nowrap` 之外的普通声明。

**渲染变化**：卡高 ≈ 111px → ≈ **77px**（-34px）；目录输入框由整行宽（≈900px）收至 ≤320px；三列顶标签齐平；「浏览.../打开」贴卡右缘，余量不再堆在框内。

### 乙案（最小改动·目录列保留三行）

只加 `fallback-card` 的 `align-items:flex-start` + 目录列 `flex:0 1 320px; max-width:320px`，不加 `.dir-input-line`。卡高仍 ≈111px（省不掉高度），但混排感消除。适合「先见效、后补高度」的两段式落地。

### 丙案（目录整行同行，整卡压到最扁）

`.path-row` 改回行向（label+输入+钮 同行）→ 列高 30px，卡高 ≈ **77px**，且目录框仍可给到 480px。但前两列是顶置标签、目录是行内标签，**仍是两种视觉语言**，与 owner「三列与整行框混排视觉杂」的原诉相悖。列为备选，不推荐。

## 4. 兜底与并发卡（一行 5 控件分组 + 并行行归位）

### 甲案（推荐·三语义组 + 并行组右锚）

**分组**：① 兜底（接管模型下拉 + ⟳ 刷新 + 「云端故障时本地接管」开关）；② 批量（批量·本地 / 批量·云端）；③ 并发（并行下拉）。每组用 `.ctrl-group` 包成一个不可拆散的原子。

**结构（`index.html` :348-375 内新增 3 个 `div.ctrl-group`，零 id 变更、控件 id 全部原地保留）**：

```html
<div class="field-row">
  <div class="ctrl-group">
    <label class="inline-field">接管模型 …</label>
    <label class="inline-field">…云端故障时本地接管</label>
  </div>
  <div class="ctrl-group">
    <label>批量·本地 …</label>
    <label>批量·云端 …</label>
  </div>
  <div class="ctrl-group ctrl-group--trailing">
    <label class="inline-field">并行 …</label>
  </div>
</div>
```

**CSS**：

```css
.fc-card > .field-row { gap: var(--space-2) var(--space-5); align-items: center; }
.ctrl-group { display: inline-flex; align-items: center; gap: var(--space-2); flex: 0 0 auto; }
.ctrl-group--trailing { margin-left: auto; }   /* 同行贴右；折行时贴第二行右缘，不再孤零零贴左 */
```

- `.fc-card` = 给 `:346` 的 `.stack.form-card` 加的 class（零 id）。
- 组内 `gap: var(--space-2)`（8px，控件咬合），组间 `var(--space-5)`（24px，分组显形）——两级间距是「分组」的全部视觉手段，且两者都在 gap 允许集内。
- 可选微修：`:361/:363` 两个裸 `<label>` 挂 `.inline-field`，让「标签—数字框」间距统一为 4px（现为浏览器默认空格）。

**渲染变化**：宽度账（`--font-xs`=12px、`--h-ctl-sm`=30px 口径下估算）——组① ≈ 56+4+170+4+34 + 8 + 18+4+154 ≈ 452px；组② ≈ (56+4+70) + 8 + (56+4+70) ≈ 268px；组③ ≈ 28+4+60 ≈ 92px；组间 24×2 = 48 → 合计 ≈ **860px**。1440 窗 + 右栏展开（主区内容 ≈848px）时仍会折行一次，但「并行」组整体贴第二行右缘；1920 折叠态（≈1600px）整行放下，5 控件一行且三组分明。卡高不变（仍为单行控件高 30px + `.group-title` 18px + gap 12px + padding 24px ≈ 84px）。

### 乙案（零 DOM 改动·仅调间距）

`.field-row` 改 `column-gap: var(--space-5)`、`.field-row > label { margin-left: var(--space-3) }` 作视觉分隔。省掉 3 个包装元素，但**没有分组容器**，「批量·本地/云端」与「接管模型」在语义与视觉上仍是一串同权控件，窄窗折行时无法保证组内不拆散。仅当实现窗口极紧时用。

## 7. 钉约束清单（实现卡必须逐条核对）
