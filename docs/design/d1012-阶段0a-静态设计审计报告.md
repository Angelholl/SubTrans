## 0. 结论先行

1. owner 自述"视觉效果和布局不合理但说不清"，可被本报告 **3 条 P0 主因** 覆盖约八成：① 三层表面明度差≈0 导致三栏分层塌缩（实测 主区↔右栏 **1.000:1**）；② 字号 token 化是半成品，**49 处硬编码 px 字号中 24 处低于 token 最小值**；③ 字重体系在 Windows 实际只剩 400/700 两级，**46 处字重声明里 41 处渲染结果相同**，层级被迫全压到字号上 → 字号被一路压小。
2. **P0-1 不是"新 UI 抄旧病"，而是"新 token 没有被分配到层级上"**：色值逐字照抄 handoff §5 且抽查一致，但 `--bg`/`--surface-2` 被同时分配给三个栏区，明度差天然为 0。
3. **可访问性有 4 组硬不达标**（`--text-3` 白底 2.54:1、`--warn` 于 `--warn-soft` 2.07:1、主按钮白字 3.68:1、键盘焦点环被 `button:focus{outline:none}` 特异性吃掉）——与观感无关，属**必须修**，不需 owner 勾选。
4. 本轮新发现（上轮未列）：**P1-11 质量页首屏是两张被 `flex:1` 强制撑高的卡，第一张内容只有一行 `<summary>`、下方约 380px 纯白空盒**（`<details>` 默认闭合 + `.console-section{flex:1}` 双重作用），这是实测最刺眼的单帧。
5. 复核补全后，基线偏差由上轮 ≥3 处扩为 **17 项**（含 6 项"已达标"反向确认），详见《d1012-阶段0a-基线偏差裁定表.md》。
6. **一处需修正上轮表述**：`UI-REDESIGN-HANDOFF.md:105` 明写左栏"浅灰 `#F9FAFB`"、§5 注 `--bg #F3F4F6` 为应用背景——**现状色值分配与 handoff 字面一致**。故 P0-1 的性质是「**handoff 规范内部自相矛盾**（左栏 #F9FAFB 与应用底 #F3F4F6 明度差仅 1.053，三区无法分辨）」，而非「现状偏离 handoff」。A1-② 推荐仍成立，但理由改为"**修订 handoff 的层级分配，而非回到 handoff**"→ 需 owner 拍板（裁定表 B-18）。

## 2. P0 — 必修项（不依赖 owner 勾选）

### P0-1 三层表面明度差≈0，三栏工作台分层塌缩

| 关系 | 色值 | 对比度 | 判定 |
|---|---|---|---|
| 左栏 `.rail`（`--surface-2`）↔ 中栏 `.main`（无 bg，透 `--bg`） | `#F9FAFB` vs `#F3F4F6` | **1.053:1** | 近乎同色 |
| 中栏 `.main` ↔ 右栏 `.aside`（`--bg`） | `#F3F4F6` vs `#F3F4F6` | **1.000:1** | **完全同色，仅 1px 线分隔** |
| 卡片 `--surface` ↔ 底 `--bg` | `#FFFFFF` vs `#F3F4F6` | 1.101:1 | 弱 |
| `--surface-2` ↔ `--surface`（hover 态） | `#F9FAFB` vs `#FFFFFF` | 1.045:1 | **hover 几乎不可见** |
| `--border` ↔ `--surface` | `#E5E7EB` vs `#FFFFFF` | 1.238:1 | 边界主要靠它 |

**根因**：`style.css:21-24` 定义三层值；分配在 `style.css:189-196`（rail=`--surface-2`）、`style.css:362-368`（main 无 background，透 body `--bg`）、`style.css:422-430`（aside=`--bg`）。**色值与 handoff §5 逐字一致，问题在分配**——`--bg` 同时给了 main 与 aside。

**与 handoff 的关系（本轮修正）**：`UI-REDESIGN-HANDOFF.md:105` 明写左栏"浅灰 `#F9FAFB`"，§5 注 `--bg` 为"应用背景"→ **现状符合 handoff 字面**。但 §6 又写"中栏（主工作区，白卡片）/右栏（配置面板，白色卡片）"，与左栏 #F9FAFB 组合后在 1.053 明度差下**无法产生三区感** → 判定为 **handoff 规范内部自相矛盾**，需 owner 在裁定表 B-18 拍板。

**对应截图**：`%TEMP%\uiredesign\light.png`、`darkns.png`

**深色侧同病**：`--bg #0B0F17` ↔ `--surface #141821` = 1.080:1；`--surface-2 #1A202B` ↔ `--bg` = 1.174:1；`--border #262D3B` ↔ `--surface` = 1.286:1。

### P0-2 字号 token 化是半成品：49 处硬编码，24 处低于 token 最小值

- `style.css:87`：`--font: 14px; --font-sm: 13px; --font-xs: 12px;`
- `style.css:139,143`：`html { font-size: var(--font) }` / `body { font-size: var(--font) }`
- 硬编码分布：**11px × 22**、10px × 2、12.5px × 5、12px × 6、13px × 4 …

**11px 出现行号（22 处全列）**：`style.css:286`（导航分组标题）、`:354`（rail 页脚注）、`:681`（文件路径）、`:691`（状态 chip）、`:812`（折叠图标）、`:1010`（系统状态 stat）、`:1081`（词典 kind chip）、`:1161/:1164`（诊断网格 k/v）、`:1207`（模型面板路径值）、`:1273`（模型 chip）、`:1499`（词库表头）、`:1516`（词库别名）、`:1542`（pill）、`:1566`（feature-badge）、`:1580/:1582`（feature-icon/text）、`:1645`（质量页）、`:1769`（右栏 badge）、`:1818`（下载进度文本）、`:1887`（状态点标签）、`:2660`（校对页 mono）、`:2808`（队列 pill）。
**10px**：`style.css:812`、`:1174`。

**判定**：这些位置**全部是信息密度最高的元数据层**（路径、chip、表头、徽章、诊断值）。token 最小值 12px 被系统性绕过 → owner 感受的"字太小/看不清"有 24 处实据。与 `UI-REDESIGN-HANDOFF.md:40` 头号诊断"字号历轮极限压缩"同源，**改版后未消除，只换了存在形式**。

**次生问题**：`index.html:1007,1016` 内联 `font-size:12.5px`；`index.html:603` 内联 `color:var(--muted, #888)` —— `--muted` **不是既有 token**（`style.css` 无定义），靠 fallback 兜底，说明内联在引用不存在的变量。

### P0-3 字重体系在 Windows 实际只剩 400/700，层级被压平

- `style.css:89`：`--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` → Windows 命中 **Segoe UI（拉丁）+ Microsoft YaHei（中文）**，两者同族仅 400/700。
- `style.css` 字重分布：**600×31、650×5、550×5、500×4、400×1 = 46 处**。
- 按 CSS Fonts 字重匹配算法：`550/600/650 → 700`，`500 → 400`。

| 声明 | 实际渲染 | 涉及组件 |
|---|---|---|
| `550`（5 处） | **700** | `.btn`(`style.css:832`)、`.file-name`(`674`)、`.field-label`(`1339`) |
| `600`（31 处） | **700** | `.group-title`(`1326`)、`.block-title`(`1332`)、`.stage-group-title`(`411`)、`.section-header h2`(`477`) |
| `650`（5 处） | **700** | `.page-title`(`371`)、`.brand-name`(`219`) |
| `500`（4 处） | **400** | `.side-tab-btn`(`242`) |

→ **46 处声明塌缩为 2 个视觉档**：`.page-title`(650) 与 `.block-title`(600) 视觉完全相同。**层级本应由字重承担，实际只能靠字号与颜色承担 → 字号被一路压小（P0-2）**。这是"说不清哪里不合理"的最高嫌疑技术根因。

**需真机确认** → `[INFO_GAP]`（`docs/design/ui-phase2-真机走查清单.md` A 节已问"微软雅黑字重观感"但未当作问题）。

## 6. 与 impeccable `detect` 的对照预期（跑之前先看这张表）

阶段 0a 若执行 `npx impeccable detect --json .`，以下命中**属已锁基线的既定决策，应预置豁免**，否则报告会把 handoff 决策全判违规：

|---|---|---|
| side-tab borders | `.side-tab-btn.active` `box-shadow: inset 2px 0 0`（`style.css:250-255`） | 豁免（导航激活指示既有语言） |
