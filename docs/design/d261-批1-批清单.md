### 1.1 钉⑤解冻提案正文（cap 192→200）

- **动机**：静态键 cap 192 已满额（D2026-1001-03 确立于预算上限 178/192，
  aggregateWindowSel +1 恰达 192）。2.6.1 校对视图三批（批 2a/2b/3）与后续
  UI 批需要静态键预算余量；决议 D2026-1002-07 指定扩 cap 提案=批 1 首件。
- **取值论证**：200 = 192 + 8。参照历史消耗速率（178→192 十四键耗于约五个
  UI 批，均值 ~3 键/批），8 键余量 ≈ 2-3 个 UI 批消耗，既避免逐批反复解冻
  （程序摩擦），又保持小步上限（防预算松弛）；校对页文案以 JS 态 MSG 键为
  主（设计红线），静态键需求有限。
- **本批消耗对照**：决议预估 2-4 个，实际净 0（`+tabReview` 校对占位项与
  `-guide_source_group_title` 来源卡撤编对冲）。低于预估原因：占位项仅耗
  1 键且与撤编键对冲；卡头折叠未新增文案（media_source_label /
  media_source_change_btn 既有键复用）。扩额后余 8。
- **id 增减预演**（决议要求预演 0-2）：本批预演结果 = 0 增 0 减——占位项
  无 id；来源条折叠仅挪动既有 9 个 id 的容器位置，id 全集 191 实测不变。
  批 2a 校对页为项目单批最大 id 扩张（历史单批最大 +7），届时按预算表分
  段列名+压缩 ≤10 走二级评议，本批不预支。
- **gate 基线**：gate.check 只拦"丢失"方向；本批 id 零减、键基数不变
  （192），gate 基线 191/192 数值不变，无需落盘更新。
