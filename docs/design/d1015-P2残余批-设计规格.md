## 1. P2-5 暗色硬编码蓝阴影（组件内硬编码 → token 化 + 暗侧覆盖）

### 1.1 现状勘验（HEAD 行号实测）

### 1.2 根因
阴影值以 rgba 字面写死在组件规则内，不走 `--shadow-*` token → `style.dark.css` 的变量覆盖机制（本仓"深浅差异全走变量"的既定规则，style.css:10-12）在此失效；蓝亮影在深底上成为可见光晕（深底 #0B0F17/#141821 上 35% 蓝的相对亮度远高于环境）。

### 1.3 目标态（新 token 2 枚，亮=现值、暗=中性黑影）

`:root`（style.css，插在 :72 `--shadow-md` 之后）新增：

| token | 亮主题值 | 暗主题值（style.dark.css :root，插 :77 之后） | rationale |
|---|---|---|---|
| `--shadow-primary` | `0 1px 2px rgba(37,99,235,.3)`（=现值原样收编，蓝影与亮侧按钮底 #2563EB 同源——**亮侧蓝影是基线原型原文** redesign-prototype.html:408-410，非漏改，保留） | `0 1px 2px rgba(0,0,0,.5)` | 暗侧取 owner 裁定带宽 rgba(0,0,0,.4~.6) 中值 .5；较暗侧 `--shadow-sm`（.4，:76）深半档，主按钮海拔高于卡片，层级不塌 |
| `--shadow-brand` | `0 2px 6px rgba(59,130,246,.35)`（现值原样收编） | `0 2px 6px rgba(0,0,0,.5)` | 品牌块 6px 扩散半径保留（形不变、色中性化）；与 `--shadow-brand` 亮值同构仅色异，是"亮侧品牌辉光 / 暗侧中性投影"的最小表达 |

**同族合并评估（任务要求）**：
- **不建议并入 `--shadow-sm/md`**（乙案，留痕否决）：①语义不同——sm/md 是中性海拔（双层 rgba(16,24,40,…)），本 2 枚是"品牌源色投影"，暗侧需要独立覆盖值而 sm/md 暗值（.4）对主按钮偏低；②若直接把 `.btn-primary` 阴影换成 `var(--shadow-sm)`，亮侧蓝影被抹 = **改动基线原型明文视觉**（P2-5 owner 只裁暗侧"漏改"，未裁亮侧）；③合并后仍需为品牌块单列值（6px 扩散 vs sm 的 2/3px），省不掉 token 数。
- 结论：**新增 2 枚语义 token（甲案）**，`--shadow-sm/md` 不动。

```js
// setDot 改为全集切换（app.js:3651-3655 原地改）
setDot(state) {
    if (!this.statusDot) return;
    const cls = { idle: 'dot-idle', running: 'dot-running',
                  ok: 'dot-ok', warn: 'dot-warn', err: 'dot-err' }[state] || 'dot-idle';
    ['dot-idle', 'dot-running', 'dot-ok', 'dot-warn', 'dot-err']
        .forEach(c => this.statusDot.classList.toggle(c, c === cls));
}
```
