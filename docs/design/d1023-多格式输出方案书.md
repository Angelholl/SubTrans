## 2. 总体设计分叉：平行附加写出（推荐）vs 替换写出

**推荐：平行附加写出**——终稿 SRT 恒常写出（现行为一字不动），ASS/VTT 作为**附加成品件**按 opt-in 写出：`{stem}_final_cn.ass`、`{stem}_final_cn.vtt`。

理由（替换写出=终稿只出 ASS/VTT 不出 SRT，会击穿四个既有契约面）：
1. 压制链 `_resolve_final_subtitle` 只拼 `.srt` 候选（`api.py:5253`）——开工令明言本任务不强制改压制链；
2. 校对页 `refine_review_load_srt` 仅 SRT 语法解析（`api.py:4815-4849`，评估包 §3.2 已点名此边界）；
3. GUI 完成检测/成品件备份清理表/`test_manifest_model.py:543` deliverables 元组全部锚定 `_final_cn.srt`；
4. 「输出默认仍 SRT」的开工令边界在替换语义下无法自然表达。

平行写出下上述四面**零改动**；附加件是纯增量。但评议（critic HRO-1）指出存在**第五面：附加件与终稿的一致性维护**——终稿 SRT 写点不止一处（见 §3），采纳其方案 A：附加件在**全部终稿写点**统一再生成，不留静默失同步窗口（详见 §10 评议回应）。

## 3. 出口层落法（三案共同底座）

改动收在出口层，管线本体（entries `{"index","timing","text"}` 表示）不动：

- 新增 `subtransjav/refine/output_formats.py`：entries → ASS/VTT 文本（pysubs2 1.8 原生 `to_string(format_="ass"/"vtt")`，零新依赖）+ 统一 helper `sync_extra_outputs(final_path, entries, formats)`（formats 空集=零行为）。实现细则（critic 实证坑，C2–C6 采纳）：
  - 多行文本必经 `SSAEvent.plaintext` setter（`\n`→`\N`），直写 text 会产出破损 ASS（pysubs2 1.8.1 实证）；
  - ASS 时间戳为 centisecond 精度（`H:MM:SS.cc`，10ms 舍入），VTT 保留 ms——验收口径按此分档（C3）；
  - 出口前剥离残留 `{\...}` override 串；VTT 转义 `&`→`&amp;`、`<`/`>` 按需（C4）；
  - 零时长 event 规范化 `end = start + 1ms`（VTT 规范要求 end>start，浏览器丢弃零时长 cue）（C5）；
  - ASS 样式集**显式构造**，字段对齐压制链 force_style 模板（`hardsub.py:119-123`，Microsoft YaHei 等），不得依赖 `SSAFile()` 默认 Arial（C6）；
  - 编码 UTF-8 无 BOM（与 SRT 出口一致；libass/主流播放器兼容）。
- **终稿写点共四处**（critic HRO-1 实证，现读复核确认），helper 在四处写点后统一调用：
  1. `pipeline_v2.py:1607`（管线终稿）——formats 取自 `RefineConfig`；
  2. `action_retranslate.py:558`（行动层重翻写回）——同 CLI 进程 cfg 透传（卡面核接线点）；
  3. `api.py:6124-6125`（全链自动补行写回）——GUI 侧，**formats 从已存在的附加件反推**（同目录 `{final_stem}.ass/.vtt` 在场即再生）；
  4. `api.py:6563`（全链回滚写回）——同上。

  **一致性契约（统一语义）**：附加件一经 opt-in 产生，此后**任何**终稿写点都同步再生；写点**不凭空新增**附加件（管线/行动层看 cfg 旗标，全链 GUI 写点看文件在场）。该语义同时天然满足 C9（后勾选不追溯补出）。
- `v2_outputs.py` 命名契约单点扩展：附加件名 = `final_stem(stem, target_lang) + ".ass"/".vtt"`（target 感知，经契约单点），全仓只许经此取（契约注释语义延伸）；备份表 `:225-229` 追加两行（`_final_{final_suffix()}.ass`/`.vtt`，存在才备份，语义同现有）。**C7 裁定**：备份表现行 `.srt` 行用 `final_suffix()` 无参（恒 cn），非 zh 方向终稿不备份属**既有 quirk**；本批附加件备份行照同一模式（与 `.srt` 行为一致），**不顺手修既有 quirk**（修=行为变更超卡面），登记为已知限制：非 zh 方向的成品件（含附加件）不进备份表。
- `RefineConfig` + `refine/cli.py` 新增参数（见 §5）。
- manifest 不记录附加件（outputs 仍 `{"A","final"}`，final=SRT）——附加件生命周期跟随备份表，不入断点续跑判定面。

## 4. 待拍板口径一：样式保真三案（决定工作量主变量）

### 案甲：格式容器转换（推荐本批）
- **做法**：附加件用统一默认样式（ASS 一套 `[V4 Styles]` 默认集，对齐压制链 force_style 语义：Microsoft YaHei 等，`hardsub.py:119-123`；VTT 无样式段）。翻译文本按终稿时间轴写 event。
- **输入前提**：无——任何输入格式（SRT/ASS/VTT 导入）都适用。
- **保真度**：仅格式容器；原样式全丢（与现状压制 force_style 语义等价）。
- **工作量**：3–5 人日（出口层+命名契约+备份表+CLI/GUI+测试钉）。
- **风险**：低。纯增量，默认关=零行为变化。

### 案乙：样式段原样保留（开工令定义需修正后评估）
- **开工令原定义**（导入时缓存原 ASS styles + 输出时 event 级按原文档对齐映射译文）**不可行**，现读证据：
  - 导入侧无任何样式缓存通道（`convert_file` 返回 dict 只含 srt_path+告警统计，原路径不落盘）；
  - **event 级对齐无可靠锚**：终稿时间轴≠原文档时间轴——导入转换本身做过重叠顺延（`test_subtitle_convert.py` 钉），行动层还会合并/拆分/重翻（action_retranslate），译文 event 与原 ASS event 不存在 1:1 映射。
- **安全形态（乙′）**：输出时按 conv.srt 同目录命名约定回捞原 `.ass`（`foo.ass.conv.srt` → 同目录 `foo.ass`），存在则取其 `[Script Info]+[V4+ Styles]` 段作**样式模板**（注意实际段头为 V4+，critic 实证），event 仍由译文 entries 生成（样式引用默认样式名）；原文件不在场（被移动/删除）自动回落案甲。VTT 输入无样式段可言，乙′ 仅对 ASS/SSA 输入有意义。
- **输入前提**：原 `.ass` 仍在导入时原位（无持久化路径，仅物理事实回捞；跨会话续跑/用户挪文件即失效→回落）。
- **保真度**：保留原字体/颜色/边框/PlayRes 等样式**定义**；event 级 override 标签（`\k` 卡拉OK、`\pos` 定位、逐字高亮）仍丢。
- **工作量**：案甲 +2–3 人日。
- **风险**：中——依赖文件在场假设；样式名引用对齐需处理（原样式名≠默认样式名时 event 引哪个样式需规格）。

### 案丙：event 级标签回嵌（不推荐实施）
- 乙′ 之上把原 event 的 override 标签映射进译文 event。**结构性障碍**：`\k` 卡拉OK 时序绑定原文逐字节奏，译文长度/断句不同即失效；`\pos`/`\move` 坐标对译文排版无语义对应；合并/拆分后标签归属无解。
- **工作量**：乙′ +5 人日起；**风险**：高，且保真承诺易成假象（标签在但渲染错乱）。
- **立场**：本批与可预见二期均不实施（采纳评议措辞放宽：保留 owner 凭具体价值信号重启口，不永久封死）；样式保真类价值由乙′ 承接。`\an` 对齐锚等低成本子集如重启可单独评估。

### 推荐
**本批做案甲**（与评估包 §3.2 范围建议一致：「不包含原始样式映射回译链，那是第二阶段议题」）。案乙′ 作为**可选后续批**，待案甲真机使用后 owner 再裁；案丙 建议关闭。
