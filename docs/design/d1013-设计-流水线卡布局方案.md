## §2 有效宽度账（316px 右栏的算术，供主审核对）

```
aside 宽                        316px（style.css:190）
 − aside 左右 padding            20×2 = 40     （style.css:447）
 = panel-card 外壳               276px
 − .panel-card padding           16×2 = 32     （style.css:516）
 = 卡内内容宽                    244px  ← 与 .pipeline-mirror 同宽，现状是齐的
 − .section-content 左右 padding 14×2 = 28     （style.css:551）
 = 输出区可用宽                  216px
```

**开关行实测**（`.encode-auto-row`：toggle 34px + `gap:6px`）：

| label | 字数×13px | 可用宽 | 折行 |
| --- | --- | --- | --- |
| MSG.encodeAutoSwitch「翻译完成后自动压制（硬字幕）」 | 14 字 ≈ 182px | 244−34−6 = **204px**（镜像层级）/ 216−40 = **176px**（section 层级） | 齐平标题层级时单行；**掉进输出区层级内即 2 行**（现状即此态） |
| MSG.fullchainAutoSwitch「翻译完成后自动执行：分析→批量修复→复验（含自动压制排布）」 | 29 字 ≈ 377px | 同上 | **≥3 行**（377 ÷ 176 ≈ 2.14） |

**路径行实测**（`.path-row`，`flex-wrap: nowrap`）：

```
216 − 「输出:」label(~38px) − 浏览(~46px) − 打开(~46px) − gap 8×3(=24) ≈ 62px → #outputDir 实际显示宽
```

→ 这是 owner「输出目录与流水线本体混杂」感受的**物理根因**：不是排布错，是三层缩进把 316px 砍到只剩 62px 给路径。

## §3 分组建议（三案）

### A 案 · 三小节 + 小节标题尾 hairline（**推荐**）

```
[两阶段流水线]                          ← .block-title 卡头（1045，不动）
  阶段A 模型: — · 并行 1               ← .pipeline-mirror（1047）
 ──────────────────────────────  ← .pipeline-subhead「流水线状态」尾 hairline
 [o] 自动压制            (副行小字)
 [o] 全链自动化          (副行小字)   压制参数 ↗  ← 标题行右挂
 ──────────────────────────────
 输出目录                            ← 复用 .section-header h2 既有样式，不新增标题类
 [o] 保存到字幕同目录
 输出: [路径............] [浏览] [打开]
```

**选型理由**
1. **零新增视觉词汇**：`.stage-group-title`（style.css:426-439）已经是本仓确立的「小节标题 + 尾 hairline」语汇，卡内 `.section-header`（542）已是「标题 + 下 hairline」语汇。方案 A 只是把两种既有语汇对齐，不引入第三种。
2. **只读/写语义分层**：镜像行归「流水线状态」小节（无开关，可放心整段 hover 触发整卡跳转）；开关+参数归「自动化」；输出区自成一节。owner 说的「输出目录与流水线本体混杂」被结构上隔离。
3. **复用 `.section-header h2` 现成样式**做「输出」小节标题 = 卡内两节标题视觉等值，无需新增 `.pipeline-subhead` 的字号/颜色决策。

**落地结构建议**（零 id、零 data-i18n 零增减）：

```html
<!-- index.html:1047 pipeline-mirror 之后插入（仅新增无 id 的分组容器） -->
<div class="pipeline-subgroup pipeline-subgroup-status" data-testid="pipeline-subgroup-status">
    <div class="pipeline-subhead pipeline-subhead-text"></div>   <!-- JS 态填 MSG 键 -->
</div>
```
> 若采用「镜像行并入状态小节」的更激进版本，则把 `.pipeline-mirror` 整体移进该容器。

### B 案 · 仅 hairline 分隔（不引入小节标题）

三段之间各插一条 `border-top: 1px solid var(--border)` 的分隔行，不加任何文字。

- **优点**：改动面最小（3 条 CSS + 3 个包裹元素）、零文案、零 MSG 新键、零可访问性风险；完全落在「间距/分隔」语汇内。
- **缺点**：右栏宽 316px，靠一条线分组力度弱；owner 的「缺分组层级」只解决一半（有线无名）。
- **适用**：若主审判定 A 案小节标题文字会挤占垂直空间（本卡高度确实吃紧，见 §9），B 是退路。

### C 案 · 子卡嵌套（每节独立 `.section` 壳）

把镜像/自动化/输出三段各套一个带 `border` + `--radius` 的子卡。

- **优点**：层级最强，折叠/展开未来可挂 `section-card` 既有组件（style.css:2836-2854 已有一整套「可折叠小节」组件）。
- **缺点**：**在 316px 里塞 3 层带边框的卡 = 4 层视觉边框**（workbench 边 / panel-card 边 / 子卡边 / section-header 下边），违反卡 C「表面分层收敛」的既定趋势；且 `.panel-card .section`（527）已经特意把子 `.section` 去壳，本案等于把它反着做回来。
- **判定**：**不推荐**，与卡 C 方向相反。

**推荐顺序**：A（主）> B（退路）> C（否决）。

## §4 长文案开关行处理（三案，至少给出 A 案全案）

### A 案 · 主行短句 + 副行 `--font-xs` 小字（**推荐**）

```html
<label class="encode-auto-row" data-testid="encode-auto-row">
    <input type="checkbox" class="encode-auto-switch">
    <span class="encode-auto-text">
        <span class="encode-auto-label"></span>          <!-- 短句，JS 态填 -->
        <span class="encode-auto-desc"></span>           <!-- 长句说明，JS 态填 -->
    </span>
</label>
```

```css
.encode-auto-row,
.fullchain-auto-row {
    display: flex;
    align-items: flex-start;            /* 顶部对齐：多行文本不再相对 toggle 居中漂 */
    gap: var(--space-2);                /* 现状内联 gap:6px 字面 → 归一 */
    cursor: pointer;
    padding: var(--space-1) 0;
}
.encode-auto-text { display: flex; flex-direction: column; gap: var(--space-hair); min-width: 0; }
.encode-auto-label { font-size: var(--font-sm); color: var(--text-1); }
.encode-auto-desc  { font-size: var(--font-xs); color: var(--text-3); }
```

**文案切分建议**（JS 态填充，**不新增 data-i18n 键**）：

| 位置 | 建议文案 | 来源 |
| --- | --- | --- |
| 主行 · 压制开关 | 自动压制 | 新增 MSG 键 `encodeAutoShort` |
| 副行 | 翻译完成后自动压制（硬字幕） | **直接复用既有 MSG.encodeAutoSwitch**，零信息损失 |
| 主行 · 全链开关 | 全链自动化 | 新增 MSG 键 `fullchainAutoShort` |
| 副行 | 翻译完成后自动执行：分析→批量修复→复验（含自动压制排布） | **复用既有 MSG.fullchainAutoSwitch** |

**理由**：① `MSG` 字典（app.js:114/116/192 区）**不在 FROZEN 快照面内**——快照只冻 `index.html` 的 id 集(223)/data-i18n 键集(186)，JS 态加键不受钉约束（但仍建议先查重再命名）；② 长句降级为副行后**信息零损失**，主人机扫读时先读到「自动压制/全链自动化」这 5~6 字决策项，展开式细节留给副行；③ 副行 `--font-xs`(12px) + `--text-3`，在白底上降为二级信息，不与标题竞争。

**渲染变化**：单行高度由 ≥3 行（约 63px）降至约 40px（主行 13px×1.55≈20px + hair 2px + 副行 12px×1.55≈19px + padding 8px ≈ 49px），两行合计省约 30~40px 垂直空间——直接缓解 §9 的高度预算。

### B 案 · 图标 + 短句（副文案上收进「说明」气泡/tooltip）

toggle 行前加 Lucide 图标（`film` / `workflow`），长句整句缩为 tooltip。

- **优点**：行高回到单行，最省空间。
- **缺点**：tooltip 承载功能说明在桌面 GUI 里是**可发现性反模式**（owner 要主动悬停才看到「含自动压制排布」这种关键限定词）；且静态中文 tooltip 受 `test_html_has_no_unmarked_user_visible_chinese` 红线约束，必须 JS 回填，多一层隐性成本。
- **判定**：仅当主审判定 A 案副行仍嫌高时，取 A 的主句 + B 的 tooltip 作为组合，但 tooltip 内容仍需 JS 回填。

### C 案 · 单行 nowrap + ellipsis（**否决**）

沿用 `.pipeline-mirror`（1157-1159）同款截断。

- **否决理由**：`.pipeline-mirror` 可截断是因为它是**只读镜像**，被截断的信息在引擎页另有完整来源；两个开关是**唯一的一处配置入口**，截断即等于隐藏语义（「含自动压制排布」被切掉会直接导致 owner 误判行为链）。**只读可截断 / 可写必全显**是本卡的第一原则。

## §5 「参数」按钮就近归属

**现状**：`.encode-params-link`（1068）在两个开关 label 之后，`margin-top:4px`，纯 `.btn-compact` 文字钮（30px 高、12px 字）。它开的是**压制参数弹窗**（`openModal({editOnly:true})`，app.js:9356-9359），与同卡的输出目录**毫无关系**——混排在语义上就是错的。

**推荐（A 案配套）· 上挂到「自动化」小节标题行右端**

```css
.pipeline-subhead-row {
    display: flex;
    align-items: center;
    justify-content: space-between;
    gap: var(--space-2);
}
.encode-params-link { margin: 0; }        /* 清掉 1068 的内联 margin-top:4px */
```

- **归属理由**：按钮弹的是「压制」参数弹窗，与两个「压制/全链」开关同域，挂小节标题右端 = 一眼可归。
- **文案建议**：MSG.encodeParamsLink 现值「参数」过泛（卡内还有输出参数语境）。**优先复用既有键 MSG.encodeAdvOpenBtn「打开压制参数」**（app.js:191，已在高级参数页使用），零新增键；若主审嫌长，退而用新增 MSG 键 `encodeParamsShort`「压制参数」。
- **形态建议**：保持 `.btn-compact` 文字钮即可。若要与 `chevron-right` 呼应可加图标钮变体，但 316px 卡内标题行 + 「压制参数」4 字已接近满行，**加图标会挤出标题**，故不加。
- **注意**：按钮**必须在小节标题行之外 label 元素**（1065-1067 注释已点明：label 内点击会透传切换开关），标题行是 `<div>`，天然满足。
- **交互风险（现状既有，非本方案引入）**：该按钮的 click 只 `preventDefault`（app.js:9357）**未 `stopPropagation`**，冒泡到 `#pipelineCard` 的整卡跳转监听（app.js:9171）会一并触发 `switchTab('tab-engine')`。上挂后需另卡统一处理，详见 §11.1。

## §6 输出目录区的融入方式

**原则**：输出区**不再套在「自动化」语义域内**，但也**不退回独立右栏卡**（卡I 已拍板整合位，卡J 不得推翻）——做法是**给它独立小节 + 拆掉多余缩进 + 给路径行腾宽**。

### 步骤 1（必做）· 拆掉卡内 `.section-content` 的多余缩进

```css
/* 现状 316px 内的第三层缩进，正是 §2 里 #outputDir 只剩 62px 的成因 */
#pipelineCard .section-content { padding: var(--space-3) 0 var(--space-2); }
```
- 输出区左边界由 30px 回到 16px，与上方 `.pipeline-mirror`、卡头标题**左对齐成一条线**（视觉一致性收益最大的一步）。
- 作用域限定 `#pipelineCard`，不波及其他页的 `.section-content`。

### 步骤 2（必做）· 路径行让宽——按钮改图标钮

```css
#pipelineCard .path-row .btn { padding: 0 var(--space-2); }  /* 「浏览」「打开」文字 → 图标 */
```
两枚 `.btn-compact`（30px）改为**纯图标**：浏览 = Lucide `folder-search`、打开 = Lucide `folder-open`（内联 svg 照 index.html:93 既有先例，零外部资源）。
- 收益：`padding: 0 10px`（20px）+ 文字宽（~26px）× 2 枚 ≈ 省 **92px**，路径输入框从 ~62px → **~154px**。
- 可访问性：图标钮必须 `aria-label`——但按钮上的 `#browseOutputBtn`/`#openOutputBtn` 是**既有 id**，其文案键 `browse_btn`/`open_btn` 在 `data-i18n` 键集内（冻结 186）。**推荐做法**：保留 `<button>` 上的 `data-i18n` 静态中文（既有键，零增减），把图标包进 `<span aria-hidden="true">`，中文保留为**可见**小字或 `aria-label` 由 JS 键回填——**实现时须主审拍板**（本卡只给方案）。

### 步骤 3（可选）· 折叠「输出:」label

`label.path-row-label`「输出:」（~38px + gap）若仍嫌挤，可把它并入 `.output-source-toggle` 那一行右侧（同行两端对齐），路径行只留 输入框 + 两枚图标钮，可再省 46px。

## §11 风险与遗留（提请主审注意）

1. **整卡跳转冒泡的真实风险（现状既已存在，非本方案引入）**：`#pipelineCard` 整卡 click → `switchTab('tab-engine')`（app.js:9171）。卡I 只在 `.destination-section` 上挂了 `stopPropagation`（app.js:9185-9189），**两个自动化开关 label 与 `.encode-params-link` 均未阻断**——勾开关或点「参数」的同时会一并触发跳转引擎页（参数按钮只 `preventDefault`，app.js:9357，未 `stopPropagation`）。本方案把「参数」上挂到小节标题行后，**该行位于任何既有阻断面之外，风险面不变但更显眼**。建议实现卡顺带把阻断面上提到 `#pipelineCard` 内的交互容器层级（属行为面，须另卡拍板，不在本件范围）。
2. **竖排动词箭头宽度**：「分析→批量修复→复验」中的 `→`（U+2192）在 `--font-sans` 下的实际步进宽需真机核对；若接近全角，副行行数可能比 §2 估算再多 1 行。
3. **`align-items: flex-start` 的副作用**：toggle 滑块（34×18）将贴文本首行顶部而非视觉居中。若真机判定偏上，替代方案是给开关行 `padding-top`（token 化，如 `var(--space-2)`）补偿——**不新增非 token 间距**。
4. **小节标题中文走 JS 态**：需新增 1~2 个 MSG 键（「流水线状态」/「自动化」）。MSG 不在快照面，但**实现时须先 grep 查重**，并按仓内既有命名法（如 `pipelineGroupStatus`）落键。
5. **小节标题与「输出目录」标题的视觉等值**：`.pipeline-subhead-text` 复用 `.stage-group-title`（`--text-2` + 尾 hairline），而输出区标题走 `.section-header h2`（`--text-1` + 下 hairline）。两者字号同为 `--font-sm` 但**字色与 hairline 方位不同**，真机上可能出现「三个标题两种样式」的不齐感。可选统一为「`--text-2` + 尾 hairline」，代价是给输出区加一条覆盖规则改字色——留给主审走查裁定。
6. **本件零代码**：本文件所有类名（`.pipeline-subgroup`/`.pipeline-subhead-row`/`.pipeline-subhead-text`/`.encode-auto-text`/`.encode-auto-desc`/`.fullchain-auto-text`/`.fullchain-auto-desc`）均为**新提案**，仓内当前零存在；实现卡需同步补静态钉（卡G2 已把折叠钮结构钉挂在行为卡，实现时同理）。
