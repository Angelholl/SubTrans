## 背景与根因

exec.v1 契约与轮转链内建于 wrapper，但契约健康度与 DEFAULT_CLI（`D:\OpenCode\resources\opencode-cli.exe`，exec_wrapper.py:27）无月度巡检点：CLI 被上游升级（size/mtime 变）或 wrapper 契约漂移时，故障只在真实跑卡时才暴露。D2026-1020-05 健康检查三件套=月度 L2（假 CLI＋size/mtime 事件检测＋版本哈希比对），激活前 L3 另计，本卡只做 L2。

## 改法

1. **假 CLI 注入断言**：以 stub（不调真 OpenCode、不经网络）产出 exec.v1 形态 payload，断言 `schema=="exec.v1"`，且 stdout 单行/stderr 进度/artifacts 落盘三件与 wrapper 现算逻辑逐字一致。断言三戒照办：2>&1 合流 stderr、逐字复制被测计算链、上真数据前过已知答案小样例。
2. **DEFAULT_CLI size+mtime 事件检测**：读 `cli-baseline.json`（size、mtime_ns、sha256），与当前实值比对；任一变化=事件行（含旧值/新值/时间），无变化=静默；基线缺失=首航生成（生成即注明，不算事件）。
3. **版本哈希比对**：sha256 入基线，变化即事件（与 size/mtime 同报，注明"上游升级嫌疑"）。
4. **自测模式 `--selftest`**：临时目录内构造已知答案小样例（假 CLI 文件＋基线），先红后绿；自测不得触碰真 CLI、不得写真基线。
5. **月度入口 `--run`**：走真基线，输出单行摘要（事件数/无事件）；退出码 0=无事件、1=有事件（供巡检判定）。

## 先红后绿

- 红：`--selftest` 构造三种变化——同 size 不同 mtime、同 mtime 不同 size、内容哈希变——旧基线下必报事件（先跑必红）。
- 绿：无变化场景不报事件；三种变化全报；基线缺失首航生成不报事件。
