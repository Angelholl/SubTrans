## 0. 填表说明（先读）

1. **原口径保留**：每格最多记 3 条补充；只记"**用着别扭 / 找不到 / 看不懂**"，**不记改善建议**（改善建议由 design-expert 在阶段 2 出方案）。
2. **填法**：每个 P 编号后有两个方框 —— `☐确认（我确实觉得别扭） ☐否定（这个没问题）`；都不勾 = 未表态。格末"补充"写你自己的痛点，可写不在预标清单里的。
3. **四态定义**：
   - **主态** = 该页正常有内容时的第一眼；
   - **空态** = 首次进入 / 尚无数据时；
   - **运行中** = 翻译或分析正在跑、有进度/日志变化时；
   - **暗色** = 切到暗色主题后看同一屏。
4. **校对页无右栏**：该页激活时 JS 给 `.workbench` 挂 `no-aside` 隐藏右栏（`index.html:847` 注释），填表时右栏相关项跳过。
5. **P 编号会成为阶段 2 的回链编号**：每条改完必须能回指到"痛点 P x-x"；同时**你勾中的涉及字号/行高/间距的痛点，就是钉④ 的 S6 复议触发源**（见《token 归一提案》）。
6. **截图不入 git**：本轮渲染帧存本地 `%TEMP%\uiredesign（本机 Temp，按环境变量解析）\`（8 张：`light.png` `darkns.png` `engine.png` `asrdict.png` `glossary.png` `guide.png` `advanced.png` `review.png`），**仅本地查看，文件名隐私不入库**；若后续载入真实媒体文件名，同样只留本地。
7. 本地截图与本表页码对应：翻译=`light.png`/`darkns.png`、质量=`guide.png`、引擎=`engine.png`、ASR=`asrdict.png`、词库=`glossary.png`、高级=`advanced.png`、校对=`review.png`。
