## 一、轴1：守恒钉解冻机制

### 1.1 问题

IIFE 升顶层必改字节（删壳行 + 搬一行），`sha256(read_all()) == 787460b7…3533` 在批4 第一次改字时**必然失效**。
需要一个替代口径，同时满足：① 仍能钉死「纯字节搬运」；② 不依赖 git 历史；③ 不引入新的自证循环；④ 可逐块先红后绿。

### 1.2 候选与取舍

| 候选 | 做法 | 判定 |
|---|---|---|
| **A. 去壳载荷钉（推荐）** | 去壳提交把 `read_all()` 变成 204,006B 的载荷，冻结其 sha；此后 15 次切块该值不变 | **采纳**：单一不变量，覆盖全部字节；任何多余字节改动必红；不依赖 node/git；无自证空间 |
| B. 钉数据由 `js_sources` 按文件自动派生（承批3 §九②） | 由目录自动生成 frozen/顺序 | **不采纳**：自动派生=拿现状钉现状，**零保护力**；若改成「提交一份 manifest」则只换来单块 revert，代价是多一个产品面文件 + 一套一致性校验。批3 §九-2 已定「整批单 revert」，收益不值 |
| C. 规范化（去缩进/去注释/token 级）sha | 归一化后比对 | **不采纳**：为「允许非纯搬运」开口子，与本系列唯一总判据（流序 + 字节守恒）冲突；且需引入 JS 解析器 |
| D. 双钉 overlap（旧钉 + 新钉并存） | 过渡期两钉同跑 | **不可行**：去壳提交自身就使旧钉失效，两钉无法同时为真 |

### 1.3 新钉定义与推导（可复算）

```
P = app-main.js 字节流 − 行2 `(function () {` − 行3 `  if (window.__refineUI) return;` − 行4358 `})();`
    （行4 `window.__refineUI = true;` 保留；再把行159 整行搬到行1703 之后）
P = 204,006B
sha256(P) = 6051c666d37bf1a11b17064c1478ff91ea139860374b9e1c1f679602e546fe33
```

推导脚本（对**改动前**的 `1eb262c` 版本执行，任何人可复算）：

```python
from pathlib import Path; import hashlib
lines = Path("subtransjav/webview_gui/assets/app-main.js").read_bytes().split(b"\n")
texts = [b.decode("utf-8") for b in lines]
entries = [(i + 1, t) for i, t in enumerate(texts) if (i + 1) not in {2, 3, 4358}]
moved = [e for e in entries if e[0] == 159]
entries = [e for e in entries if e[0] != 159]
pos = next(i for i, e in enumerate(entries) if e[0] == 1703)
entries = entries[:pos + 1] + moved + entries[pos + 1:]
p = "\n".join(t for _, t in entries)
print(len(p.encode()), hashlib.sha256(p.encode()).hexdigest())
# 204006 6051c666d37bf1a11b17064c1478ff91ea139860374b9e1c1f679602e546fe33
```

**对照（证明搬移真的改了字节）**：只删 3 行、不搬 L159 → 同为 204,006B，sha256 为
`5fd2190e26f6a3b548ae5f279b3f1af6e8c629691824b5e82728fea05e8f3ba0`。两值不同，故新钉同时锁定「删 3」与「搬 1」。

**为什么这一枚钉同时证明了「去壳只删 3 行 + 只搬 1 行」**：P 是从改动前字节流算出的；去壳提交后
`read_all()` 必须逐字节等于 P。多删一行、少删一行、改一个空格、缩进变化、换行变化 → 哈希不等 → 红。
即「新钉 = 去壳补丁的指纹」，不需要第二个补丁钉。

2. 先跑 → **红**（实际仍是 `787460b7…`，期望 `6051c666…`），把红输出贴执行记录（先红证据）。
3. 执行去壳 + 重排 → 再跑 → **绿**。

5. **独立复算（防「改字节再同步改钉」）**：执行者必须从起始提交重算载荷并与产物比对，输出贴执行记录：

## 二、轴2：IIFE 升顶层可研（Q3 前置）

### 2.1 壳内符号面（实测）

- 172 个顶层符号（129 函数 + 43 const/let），**零重名**；与既有 19 个分文件顶层声明**零重名**。
- 其他文件对 172 个名字的**解析到全局的引用 = 0**；`fmtGB`（`app-modal.js:728`）是**同方法局部遮蔽**（:639 `const`），
  不是全局引用、也不是第二处行为差量（勘探 §6.1 已逐处列明）；注释级 6 处不参与解析。
- 顶层 `window.X =` 8 处（含 `__refineUI`），嵌套 3 处；12 处 dunder 全仓口径不变。

### 2.2 两案利弊

### 2.3 三项代价的处置

1. **隐式全局面**：不新增一行 `window.X =` 文本；172 个名字由「文件即边界」的逐文件 sha 钉死，
   另加一条 `test_refine_global_surface_pinned`（**冻结 172 个精确名字**：集合相等，不是只数个数）把「新增/删除/改名全局」变成必红。
2. **行为翻转（唯一）**：`app-modal.js:662` `typeof openDir === 'function'` 从假变真 → 「打开目录」按钮可用。
   方向是修复死按钮，但属运行行为变化：**接受并在 GUI 验收单列一项点验**；不为此改任何代码（改代码才是更大的差量）。
3. **元素 id 遮蔽**：`refreshFallbackModels`/`asrStatus`/`guideStatus`/`guideCustomStatus` 四个函数名与元素 id 同名。
   全仓无 `window.<这四名>` 读取（元素一律走 `$()`/`getElementById`），当前无影响；卡面登记为已知差量，
   并加静态断言「这四个 id 只经 `$(`/`getElementById` 访问」不必要（既有实现已如此），仅登记。

### 2.4 为什么不 de-indent

去壳后顶层语句仍是 2 空格缩进（原 IIFE 内缩进）。**保留缩进**是字节守恒的必然：de-indent 会让 4,300+ 行全部变化，
既毁掉逐块 sha 钉，也让每个块的 diff 变成全文重写。可读性损失由「文件边界 + 区头注释」补偿；格式化另立批次，不在本批。

### 2.5 为什么不改成模块 / 命名空间对象

- `type=module` 在 `file://` 下被 WebView2/CORS 拒载（`main.py:265-277`/`:394`，D2026-1018-01 R-C 硬约束）。
- 命名空间对象（`const RefineUI = (function(){…})()`）需要把 172 个名字的全部调用点改成 `RefineUI.x`，
  是数千处改写，属重写而非切分，违反「纯搬运」与「函数不跨文件」的最小改动原则。
