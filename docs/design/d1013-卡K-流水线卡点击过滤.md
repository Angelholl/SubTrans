## 改法

1. **改写既有 pipelineCard click 监听**（app.js :9171 区 `pipelineCard.addEventListener('click', () => switchTab('tab-engine'));`）为带过滤的处理器：
   ```js
   pipelineCard.addEventListener('click', (e) => {
       // 卡K（D2026-1013-01 真机反馈）：交互元素不触发整卡跳转（统一入口过滤）
       const target = e.target;
       if (target instanceof Element && target.closest(
               'button, input, label, a, select, textarea, .path-row, .destination-section, .encode-auto-row, .fullchain-auto-row, .encode-params-link')) {
           return;
       }
       switchTab('tab-engine');
   });
   ```
2. **改写既有 keydown 监听**（同函数区，:9173 附近）为同一过滤逻辑（keydown 的 e.target 可能是卡片本身——卡片聚焦时 Enter 应跳转=closest 不命中交互元素即放行，符合「只读区可跳」语义；守卫 `instanceof Element` 必须保留）。
3. **零新增散点阻断**：卡I 既有 `.destination-section` click+keydown stopPropagation 块**原样保留**（钉 :5176 区）；不新增任何控件级 stopPropagation。
4. **保留钉敏感串**：`pipelineCard.addEventListener('mouseenter', refreshPipelineCardHint)` 与 `pipelineCard.addEventListener('focus', refreshPipelineCardHint)` 两行逐字保留（test_pipeline_card_hint_here_pinned 断言）；`refreshPipelineCardHint` 函数本体零改动。
5. **回归钉** `test_pipeline_card_click_filter`（新钉，落 test_gui_js_static.py）：
   - 断言 app.js 中 pipelineCard 的 click 监听体含过滤清单串 `'button, input, label, a, select, textarea, .path-row, .destination-section, .encode-auto-row, .fullchain-auto-row, .encode-params-link'`；
   - 断言含 `instanceof Element` 守卫与 `switchTab('tab-engine')` 仍在（跳转语义保留）；
