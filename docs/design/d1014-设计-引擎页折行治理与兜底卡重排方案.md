## 1. 件1：阶段卡折行治理（index.html:228-259 / :275-303）

### 1.1 根因（代码核实）

form-card（:1536，flex-wrap + align-items:center）下 `.stage-row`（:1574，flex:1.2）
与 `.alt-row`（:1593，flex:1/min-width:250）是**两个各自独立折行的兄弟容器**：
stage-row 内部再折行，alt-row 作为整体在卡高内**垂直居中**——于是 API Key 组会漂到
stage-row 某一中间行（owner 608 截图「提供方与 API Key 同行」= 居中投影），模型栏与
测试钮按 stage-row 自身节奏拆行，窄时测试孤行。app.js 读写全走 id 模板
（app.js:4764/4794/5587/7980），grep 全仓 **零** .stage-row/.alt-row 选择器依赖
（app.js/review.js 选择器 0 命中；tests 仅 :5521 卡Q 注释提及 alt-row 字样，无断言）
→ 重组 DOM 对 JS 零影响。

### 1.2 目标布局（实测断点，按卡宽 W）

| W 区间 | 行形态 | 实测卡高(状态行空) |
|---|---|---|
| W ≥ 918 | 1 行：标题+提供方+模型+刷新+测试+API Key 组；状态行另起 | 64 |
| 516 ≤ W < 918 | 3 行：①标题+提供方 ②**模型+刷新+测试+API Key 组（整组恒同行）** ③状态 | 102 |
| W < 516 | 4 行降级：②内的 API Key 三件**整组**下沉第 3 行（不再与提供方交错） | 140 |

owner 基准 主区≈570（618 视口）→ 落 516..918 区间：**单元二放得下且余量 54px**
（单元二行破容量 486 ≤ 540 内容宽）；次优折行点位即 W<516 的 key 整组下沉（实测
460..510 全部为该形态，无溢出 ovf=0）。

### 1.3 DOM 改法（两卡同构；零 id、零 data-i18n、零锚注释变化）

1. 删除 `.alt-row` 包裹层（:252-258 / :296-302 的 div 壳），其三个子元素原样保留；
2. 在 provider select 之后开 `<div class="stage-unit">`，model/刷新/测试三件保持原序入内；
3. 测试钮之后、status span 之前插 `<div class="stage-key">` 包住原 alt-row 三件
   （label API Key / key input / 保存钮），随后闭合 stage-key 与 stage-unit；
4. status span 留在 stage-unit **之外**、stage-row 之内（order:99/basis100% 语义不变）；
5. `<!-- 阶段A 完整行 -->` 等 4 枚切片锚注释（tests:5657-5661）逐字不动；
   注释块、data-i18n-title、data-i18n-placeholder 一概随元素整体搬运，不改值。

### 1.4 CSS 改法（style.css，全部落在 §11「引擎页 form-card/stage 行」区）

**新增 3 个宽度 token**（挂 :115-141 内联宽度 token 区，先例 --w-agg-window:141）：

```css
--w-stage-model: 140px;   /* 阶段模型框下限 = flex basis，长 option 下可收缩到 140 */
--w-stage-unit: 520px;    /* 单元二行破下限（486 实测 + 34 余量） */
--w-stage-key: 240px;     /* API Key 三件原子组下限（label42+140+36+gap16=234 +6） */
```

**新增两规则**（接替被删的 .alt-row 块 :1593-1599 位置）：

```css
.stage-unit { flex: 1 1 0; min-width: min(var(--w-stage-unit), 100%);
              display: flex; align-items: center; gap: var(--space-2); flex-wrap: wrap; }
.stage-key  { flex: 1 1 0; min-width: var(--w-stage-key);
              display: flex; align-items: center; gap: var(--space-2); }
```

要点（均有实测背书）：
- 单元二用 **basis 0 + 显式 min-width** 才能恒同行：flex 包裹容器的自动 min 是
  「最长子项」而非各项之和，且模型 option 由 JS 注入长度不定——显式 min 让行破判定
  与 option 长度解耦（实测：长 option 时单行阈值仍恰为 918，未漂移）；
- `.stage-key` 必须给**显式 min-width**：key input 的 min-content 固有 170（size 固有宽）
  大于 min-width 140，容器自动 min 会把行破阈值顶到 510（实测：无显式 min 版在
  内容宽 510 恰合、500 即拆行）；显式 240 覆盖自动 min 后阈值回落 486
  （有 min 版实测 516 卡宽即同行，余量 54）；
- `min(..., 100%)`：W<520 时 min-width 收敛为 100%，避免极窄窗溢出（460..510 ovf=0 实测）。

**旧规则处置**：

| 规则 | 处置 |
|---|---|
| `.stage-row` 全部（:1574-1583） | **留**（成为唯一行容器，flex:1.2 在单子元素下无害） |
| status 组（:1584-1591，order:99） | **留**，仅从选择器组中删掉 `.alt-row .muted` 一行（死选择器） |
| `.alt-row`（:1593-1599） | **删**（元素已不存在）；`--w-alt-row`(:122) token **留**（token 区「勿删」） |
| :1602-1603 标题/provider 下限 | 留 |
| :1604 `#refineS1Model, #refineS3Model, #refineCleanerConfigShow { min-width: var(--w-model) }` | **拆**：两模型改 `var(--w-stage-model)`；cleaner 移出（归件2 新规则用 `--w-cleaner`） |
| :1605 key min/max（卡Q） | **原样留**，注释同步更新 |

**二选一（推荐 A，执行按 A）**：模型框下限改法——
A. 新增 `--w-stage-model:140px` 只作用于两模型（推荐：`--w-model:200` 不动，
   index.html:552 角色卡 `min-width:var(--w-model)` 内联零波及，改动不出阶段卡域）；
B. 直接改 `--w-model` 200→140（少一 token，但连带角色卡内联下限，超卡风险）。
另：若不降模型下限，单元二行破=200+36+46+240+24=546 > owner 540 内容宽，
owner 设备必拆行——**降模型下限是硬前提**。

### 1.5 卡Q 钉与 status 兼容

- tests:5549-5560 三条断言（--w-key-input:140 / 无200 / `#refineS1Key, #refineS3Key` 组
  max-width:200）→ :1605 原样保留，逐条继续绿；key 在 stage-key 内仍 flex:1 → 实测

### 1.6 风险清单

1. 行破阈值 516/918 依赖实测宽（214/138/36/46/42/36），中英切换会平移单行阈值——
   断言面只锁结构与 token，不锁阈值像素；
2. W<516 降级区 key 整组下沉为已实测形态，但 owner 未在此宽度见过该卡，验收需走查；
3. 单行区（W≥918）保存钮右侧存在随宽度增长的余白（key 触 200 上限后余量滞留，
   实测 W=1400 时 84px）——现行 alt-row 独占约 45% 行宽、同区余白按 flex 比例推算
   更大（≈328px），属改良非回潮，记录在案；
4. 两卡结构相同，改漏阶段B 即不对称——验收断言按 A/B 双卡成对写。

## 2. 件2：兜底与容错卡重排（index.html:318-343，style.css:3097-3100）

### 2.1 根因

`:1561-1567 .form-card:not(.stack) label:has(> …) { flex-direction: column !important }`
按直系子级命中三个 label（含目录 path-row），强制「标签压控件」三层堆叠；`:3100`
目录列 `flex:0 1 320px` 固定限宽 → 右侧留白；:3097 `align-items:flex-start` 下三列顶
对齐但各列内部参差。owner 判定与高级参数页（index.html:804-826 `.field-row >
label.inline-field`）及同页兜底与并发卡（:346+ `.ctrl-group`）的「标签左控件右」语言
不一致 → 推翻卡R3 乙案（commit 4b526d8 / D2026-1013-01 第五轮），改行内化。

### 2.2 目标布局（实测断点，按卡宽 W）

| W 区间 | 行形态 | 卡高 |
|---|---|---|
| W ≥ 820 | 1 行：[兜底档位 ▾][上下文窗口 □][净语配置目录 ▭▭ 浏览 打开]，目录输入吃满剩余 | 56 |
| 440 ≤ W < 820 | 2 行：①档位+窗口 ②目录整行（label+输入+钮同行，钮 flush 右缘） | 98 |
| W < 440 | 3 行各成组（组不散） | 140 |

owner 570 → 2 行形态；实测右缘 flush=0（浏览/打开随输入同行右缀 = 阶段A 地址行语言），
ovf 全区 0。

### 2.3 改法（纯 CSS + 钉修订，DOM 三直系子级零改动）

1. **不改 :1561 本体**（其他 form-card 依赖），新增作用域 override（放在 :3097 区、
   源序在后即可压平——选择器必须凑足 (0,3,1) 特异性 + `!important` 才等价胜出）：

```css
.form-card.fallback-card:not(.stack) > label {
    display: flex !important;
    flex-direction: row !important;
    align-items: center !important;
}
/* label 内 span↔控件 4px 由 :1561 的 gap: var(--space-1) 继承，不另写 */
```

2. **:3097 原样留**（align-items:flex-start + gap:var(--space-3)，测试 m1 依赖）；
   基线对齐靠把 path-row 行高归一到控件高：`:3100` 改写为

```css
.form-card.fallback-card > label.path-row { flex: 1 1 auto; min-height: var(--h-ctl-sm); }
```

   ——320px 限宽**去**（owner「留白过多」主因）；`flex:1 1 auto` 让 max-content=373 成为
   行破 hypothetical → 阈值随内容自洽；`min-width:240` 随之删除（自动 min=内容 373，
   显式 240 是假下限）。:3098-3099（前两列 width:auto !important）**原样留**。
3. **目录输入吃剩余宽**，新规则（覆盖 :1568 的 width:100%——特异性 (0,4,1)>(0,3,1)）：

```css
.form-card.fallback-card > label.path-row > .form-input {
    width: auto !important; min-width: var(--w-cleaner); flex: 1 1 var(--w-cleaner); }
```

   同时 **:1604 摘除 `#refineCleanerConfigShow`**（id 特异性压 class 规则，必须改
   源规则而非加 override），cleaner 下限从休眠 token `--w-cleaner:160`
   （style.css:125，现全仓零引用）起用。
4. `.path-row` 本体（:1510-1516 nowrap）与 `.field-btn-row`（:1526）不动 → 钮随输入
   同行右缀。
