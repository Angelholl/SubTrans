## 3. 角色提示词模板（可选，仅当在 ZCode 中启用多智能体时使用）

> 说明：以下为按原会话真实流程拟写的通用模板，与具体工具无关；
> 粘贴时按 ZCode 实际的智能体/计划机制自行调整称呼与输出方式。
> 三个角色可串行执行：A 的输出是 B 的输入，C 独立验收。

### 角色 A · 界面侦察（对应诊断阶段）

```
目标：为 SubTransJAV GUI 改版建立实现基线，只调查、不改动。
输入：D:\SubTransJAV（重点 subtransjav/webview_gui/assets/）。
任务：
1. 枚举 index.html 全部元素 id 与 data-i18n* 属性，产出清单；
2. 在 app.js 全文搜索 closest( / parentElement / getElementById / classList，
   列出 JS 依赖的全部 class 与 id（预期含 .file-item / .console-section / .btn-audio-preview）；
3. 搜索 http:// / https:// / cdn，确认是否存在外部网络依赖（预期：除 API 端点外无）；
4. 读 style.css 的 :root 变量层与 style.dark.css，摘要现有 token 结构；
5. 记录窗口默认尺寸与缩放行为（webview_gui/main.py）。
输出：《实现基线报告》：id 清单、JS 依赖点清单、外部依赖清单、token 摘要。
禁区：不修改任何文件；不评价视觉好坏（那是角色 B/C 的事）。
```

### 角色 B · 原型/实现（对应产出阶段）

```
目标：按定稿方案实现改版，视觉与 docs/design/redesign-prototype.html 一致。
输入：docs/design/UI-REDESIGN-HANDOFF.md（唯一事实来源）+ 角色 A 的《实现基线报告》。
任务：按交接文档第 7 节路线执行；每一阶段完成后对照第 4 节硬性约束自查：
1. 所有元素 id 原样保留（对照基线报告清单逐一核对）；
2. data-i18n* 属性原样保留；
3. .file-item / .console-section / .btn-audio-preview 三个 class 保留；
4. 表单控件底层 input/select 类型不变，仅样式升级；
5. 不引入任何 CDN/网络资源；图标一律内联 Lucide SVG，stroke-width 统一 2（导航 1.8）；
6. 图标语义红线：移除/清空类操作禁止使用垃圾桶图标（不删磁盘文件），
   用 list-x / x；垃圾桶仅用于真实删除场景。
输出：可运行的 index.html + style.css + style.dark.css（5 套主题收敛为 2 套），
      附改动摘要与"约束自查表"（每条约束：通过/不通过+证据）。
```

### 角色 C · 走查审阅（对应走查阶段）

```
目标：独立验收，找证据、不给空泛意见。
输入：角色 B 的产出 + 原型文件 + 交接文档验收清单。
方法：
1. 浏览器（或应用真机）打开界面，浅色/深色各走查一遍；
2. 对照交接文档第 7 节验收标准逐项打勾/打叉；
3. 重点检查：id 完整性（对照角色 A 清单）、双主题对比度、
   Windows 125%/150% 缩放下布局、深色模式下阴影是否过亮、
   i18n 是否有未翻译键（如 "No files selected"）、emoji 残留；
4. 每个问题给出：位置（文件+行号或元素 id）、证据、建议修法、优先级（P1/P2/P3）。
输出：《走查报告》，按优先级排序；不改文件。
```

## 4. 使用建议

- 单智能体足够时不要拆多智能体（原会话即单会话完成，约 20 次工具调用）；
- 若拆分，A→B→C 严格串行，A 的基线报告是 B 的前置条件，C 必须独立于 B；
- 所有角色的共同前置：先读 `UI-REDESIGN-HANDOFF.md`，禁止凭记忆改 UI。
