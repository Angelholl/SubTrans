# d1019-批4 owner 拍板点清单（10 点，每点给推荐）

> 用途：批4 执行轮开工前，owner 逐点勾选。未勾选的点按「推荐」默认值执行；标 ★ 的三点若否，方案需改档（不是执行细节）。
> 依据：`docs/design/d1019-批4-勘探报告.md`、`docs/design/d1019-批4-方案书.md`。

## ★ P1 是否升顶层并切成 15 块（Q3 重开的核心）

- **问题**：Refine IIFE 是否拆壳升顶层，从而把 204,060B 单块切成 15 个 `app-refine-*.js`。
- **选项**：
  - **A（推荐）升顶层 + 15 块**：阶段 3 拆分闭环；代价=172 个全局符号（129 个挂 `window`）、1 处行为翻转、4 个元素 id 被同名函数遮蔽、35 个 `<script>`（34 分文件 + `review.js`）、重入守卫删除。
  - B 保持 IIFE 整块**永久定案**：零风险，但 204KB 单块永久留存、Q3 永不闭环。
- **推荐理由**：172 个名字对其他 19 个分文件**解析到全局的引用 = 0**（勘探 §6.1，`fmtGB` 为同方法局部遮蔽非全局引用），升顶层的耦合代价已被测空；不拆则前三批成果止步于「还剩一个 204KB 巨石」。
- **不拍板的后果**：批4 无法开工（去壳与切块都以此为前提）。

## ★ P2 守恒钉替代口径

- **问题**：旧钉 `787460b7…3533`（470,198B）在去壳提交处必然失效，用什么替代。
- **选项**：
  - **A（推荐）去壳载荷钉**：`sha256(read_all()) == 6051c666…fe33`（204,006B），15 次切块恒真；去壳提交只删 3 行 + 搬 1 行，任何多余字节改动必红。
  - B 「钉数据由 js_sources 按文件自动派生」：自动派生=零保护力；改成提交 manifest 只换来单块 revert，多一个产品面文件。
  - C 归一化（去壳/去注释/token 级）sha：为「非纯搬运」开口子，需引入 JS 解析器。
- **推荐理由**：新钉值是从**改动前**字节流算出的，等于「去壳补丁的指纹」；不需要第二个补丁钉，也不依赖 git 历史。
- **不拍板的后果**：执行轮无钉可打，逐块验收失去唯一总判据。

## ★ P3 `window.__refineUI` 的处置

- **问题**：`if (window.__refineUI) return;` 在顶层是语法错误（`return` 只能在函数内），必须删；但 `window.__refineUI = true;` 是 12 处 dunder 之一，D2026-1018-01 明文「禁清理既有钩子」。
- **选项**：
  - **A（推荐）保留标记、只删守卫**：`window.__refineUI = true;` 原样留在首个分文件顶部，作为**只写兼容标记**（无读方）；重入保护改由「每个 `<script>` 在 index.html 恰出现一次」静态钉承担。代价：重复加载从「静默 return」变「`const` 重复声明 `SyntaxError`」（本仓无动态注入路径）。
  - B 连标记一起删：需 owner 明示豁免「12 dunder 禁清理」红线，并改写以它为哨兵的测试。
  - C 保留完整守卫：不可行（顶层 `return` 非法，除非再包一层 IIFE，等于没拆）。
- **推荐理由**：A 零红线冲突、零测试哨兵迁移；标记无消费方但也无副作用（28B）。
- **不拍板的后果**：默认 A；若选 B，须同时改 `test_startup_chain_not_killed_by_scope_leak` 的哨兵并留豁免记录。

## P4 唯一行为翻转：ASR 模型面板「打开目录」按钮

- **问题**：`app-modal.js:662` `if (typeof openDir === 'function') openDir(dir);` 现状恒假（死按钮）；升顶层后 `openDir` 成全局 → 按钮变可用。这是全仓唯一的行为变化（勘探 §6.2）。
- **选项**：
  - **A（推荐）接受激活**：登记为「已知行为差量（死按钮修复）」，GUI 验收单列一项点验；不改任何代码。
  - B 把 `openDir` 改名以保住死分支：为保留 bug 改代码，且破坏「纯搬运」，不推荐。
  - C 删除该按钮分支：动 UI，超出拆分批量，需另立卡。
- **推荐理由**：方向是修复；改代码反而扩大差量面。**不存在第二处**：`fmtGB`（`app-modal.js:728`）绑定同方法内 :639 的局部 `const`，不是全局引用（勘探 §6.1 已勘误）。
- **不拍板的后果**：默认 A，但执行记录与 CHANGELOG 不写「行为无变化」，须写「唯一行为差量：该按钮由不可用变可用」。

  - B 改写为 class/多命名空间对象：语义重构，不在拆分系列范围。

## P7 `test_gui_js_static.py` 凭据判据误拦（3 处文案）

- **问题**：:4111/:6125/:6129 三处既有文案里，英文 token 一词后紧跟冒号或等号再接占位符/数字，会被「写入凭据字面量」判据当成密钥赋值。批4 必须改该文件的数据区，不解决就会被反复拦截（**本轮写这份文档时已被误拦一次**，判据形态属实）。
- **选项**：
  - **A（推荐）先一笔 chore 改写 3 处文案**：把英文 token 一词换成「语义变量」等中文措辞，冒号/等号后不再紧跟占位符；不动任何断言逻辑，然后正常工具写入。
  - B 沿用批3 的「owner 授权脚本通道」逐次写数据区（每次都要授权）。
  - C 不改文案，遇到拦截再人工确认。
- **推荐理由**：3 处都是错误信息/注释文本，改写零语义影响，一次性消除复发点（lessons L-20261019-01 已登记该预案）。
- **不拍板的后果**：默认 A；若否，执行轮每次写该文件都可能被拦。

- **问题**：15 块切完后 `app-main.js` 只剩 2,654B（boot 段），是删除还是保留。

## P9 切分粒度

- **问题**：15 块是否合适。
- **选项**：
  - **A（推荐）15 块**：2.3–34.7KB，按功能域聚类，最小块也有独立语义（boot/dataroot）。
  - B 合并为 ~6 块（每块 20–40KB）：提交少，但「文件=功能域」的发现性下降。
  - C 更细（`app-refine-dict.js` 再拆下载/迁移 → 16 块）：最细，但 +1 条边界与 +1 笔提交。
- **推荐理由**：与批3「一块一文件」的证据粒度一致；34.7KB 的 dict 是单功能域上限。
- **不拍板的后果**：默认 A；若选 C，单元表与 sha 需重算（本方案书作废重出）。

## P10 GUI 验收节奏

- **问题**：34 个 `<script>` 的加载与首屏行为何时验。
- **选项**：
  - **A（推荐）两次**：去壳提交后一次（验证 IIFE 消失、单文件仍正常）+ 终态一次（34 文件、全功能回归）。
  - B 只在终态验一次：省一次黑盒，但去壳若出问题会与后续 15 块纠缠。
  - C 每块一次：成本过高（16 次黑盒）。
- **推荐理由**：去壳是唯一一次「非纯搬运」，必须单独设卡；切块是纯搬运，终态一次足够。
- **不拍板的后果**：默认 A。
