## 根因（已定位）

`subtransjav/refine/quality_report.py:1400-1470` 导读条目五来源（A post_validate 告警/B untranslated/C 单行超长/D 疑似漏听/E cps_too_fast）各自 append，条目 `index` 全部取**字幕条目号**（同一坐标空间，audio_detect.py:330 证实）。同一行被多类别双标记时（真机 7 运行 6 次、共 11 对，全部 cps_too_fast×其他），裸 `#N` 引用无法区分"哪一条导读条目"——人读困惑、程序消费（action_retranslate 重翻清单打印 :284、crosscheck_detail、review 定位）按 index 反解会命中同号异类条目。

## 改动文件（一卡两文件）

1. `subtransjav/refine/quality_report.py`（guide_items 组装段+txt 章节行渲染）
2. `tests/test_quality_guide_items.py` 或既有覆盖导读组装的测试文件（执行时以 `grep -rln "guide_items" tests/` 实际命中为准，先探后改）

## 改法

1. **结构化通道 additive**：每个 guide_item 新增 `item_id` 字段＝`f"{类別码}-{index}"`（码表：cps_too_fast→CPS / untranslated→UNTR / single_line_too_long→SLN / suspected_missed_speech→SMS / post_validate 告警→PW）；既有 `index`/`category` 字段零改动（additive 双写口径，同 post_validate 结构化告警先例）。
2. **txt 章节渲染**：五来源条目行 `#{index}` 改为 `#{item_id}`（如 `#CPS-238`、`#SMS-5`）；`prev_index`/`（疑似（粗筛）#{index}）` 等交叉引用同步带码。
3. **消费端适配（最小面）**：`action_retranslate.py:284` 打印与 `:416-417` 行单已带 category，追加 item_id 透传即可；`resolve_final_block` 等**按字幕 index 反查终稿块的路径不改**（它们查的是字幕条目空间，本来就对）。
4. **json 契约**：导读 JSON 消费方（api.py crosscheck_detail/前端 guide 页）对未知新键应天然透传；执行时 grep `guide_items` 消费面确认无键集白名单，若有则同步增记。
