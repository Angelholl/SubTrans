## 2. P0-4 键盘焦点环恢复

### 2.1 根因与改法（特异性处理的确切写法）

现状（当前 HEAD 行号）：

| 规则 | 位置 | 特异性 | 结果 |
|---|---|---|---|
| `:focus-visible { outline: var(--focus-outline); outline-offset: 2px; }` | style.css:185-188 | (0,1,0) | 被压 |
| `button:focus { outline: none; }` | style.css:189 | (0,1,1) | **胜出**（鼠标/键盘一律无环） |

**改法（单行替换）**：

```css
/* style.css:189 */
button:focus { outline: none; }   /* 旧 */
button:focus:not(:focus-visible) { outline: none; }   /* 新 */
```

- 新规则特异性 (0,2,1)，但含 `:not(:focus-visible)` 闸门：**键盘聚焦时该规则整体不匹配**，全局 `:focus-visible`（:185-188）照常胜出；鼠标点击仍无环，行为与现代 UA 启发式一致。
- 不采用「直接删除 :189」：删除后鼠标点击按钮依赖 UA 自身 `:focus-visible` 启发式，在 WebView2/不同 UA 内核下不保证一致；保留显式抑制更确定（audit 报告给了两案，本规格择 `:not()` 案）。
- 不引入 `box-shadow` 焦点环：`--focus-ring`（:98）是既有 token，但全局改 box-shadow 会与 `.btn-primary` 自有阴影（:924）打架；outline 案与既有先例（:481）同构。

### 2.2 焦点环样式（出自既有 token，零新增）

- 边缘贴边控件用负 offset 先例：`.aside-toggle-btn`（:481）、`.file-item`（:719）已自带 `outline-offset: -2px`，不改。
- 对比度：焦点环 #3B82F6 对白 3.68:1 ≥ 3:1（WCAG 1.4.11 非文本对比）；暗主题 #60A5FA 对 #0B0F17/#141821 = 6.98:1+ ✓。
