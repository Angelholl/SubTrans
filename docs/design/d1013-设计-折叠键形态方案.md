## §1 问题诊断（把 owner 一句「布局不合理」拆成 4 条）

| 编号 | 痛点 | 归因 | 后果 |
| --- | --- | --- | --- |
| **Q-A** | **「悬浮方钮」的孤岛感** | style.css:492-497 折叠态 `align/justify: center` + 458-466 共规块给两钮**各画一个 30×30 带框方钮** | 44px 宽、满高的把手条里浮着一个 30px 的小方块，四周 7px 留白，**钮与条之间没有任何视觉连接**，像贴上去的贴纸 |
| **Q-B** | **把手条本身零语言** | 折叠态 aside 除那条 30px 钮外**没有任何其他元素**（内卡全隐） | 条子不传达「这里是一栏被收起来的内容」，只有「这里有个按钮」 |
| **Q-C** | **可点区与视觉体量倒挂** | 把手条实际面积 = 44 × 视口高（≥44×600 ≈ 26000px²），可点区仅 900px²（3.5%） | 视觉上大片空白却点不动，是「布局不合理」最直接的体感来源；而 44px 是 grid 列契约（§0.4）**不能加宽**——只能让**空白本身可点** |
| **Q-D** | **双态图形语汇不统一** | 展开态 = `panel-right-close`（面板+竖分割线+左箭头的复合图形，暗示「关闭面板」）；折叠态 = `chevron-right`（单纯箭头） | 两态并排出现时像两个不同组件；展开态钮贴在卡角、折叠态钮浮在条中，**位置语言也不统一** |

**诊断结论**：Q-A/Q-C 是同一件事的两面——**把「小方钮」放大成「整条把手」，让把手条本身就是按钮**，一次性解掉两条。Q-B 需要额外的把手条装饰语汇。Q-D 涉及展开态，而展开态被 §0.4 钉死，**只能有限联动**。

## §2 备选形态方案（4 案，均零新增 DOM 元素、零 id、零静态中文）

> 四案的共同底线：**44px 列宽不变**（钉 ①a/①b）、**两钮 `class` 属性保持单类名**（钉 ②）、**共规块 border/background 保持不动**（钉 ①）、**零新增静态文案**、**图标一律 Lucide 内联**。

### 甲案 · 整条把手可点 + 无框 chevron 居中（**主推**）

**形态**：把手条**整条**即展开按钮。折叠态下 `.aside-expand-btn` 撑满 44 × 满高，去边框/去圆角/去底色，只留一枚居中的 `chevron-right`；悬停时**整条**染 `--surface-2`。

```css
/* 折叠态专属覆盖（不动 458-466 共规块 → 钉① 保绿） */
.workbench.aside-collapsed .aside { padding: 0; }
.workbench.aside-collapsed .aside-expand-btn {
    flex: 1 1 auto;          /* 吃掉把手条剩余高度 */
    align-self: stretch;     /* 吃掉 44px 满宽 */
    width: auto;
    height: auto;            /* 覆盖共规块的 --h-ctl-sm */
    border-color: transparent;   /* 保留 1px 边框声明，只透明化 */
    border-radius: 0;
    background: transparent;
    color: var(--text-2);
}
.workbench.aside-collapsed .aside-expand-btn:hover {
    background: var(--surface-2);
    color: var(--text-1);
}
.workbench.aside-collapsed .aside-expand-btn:focus-visible { outline-offset: -2px; }
.workbench.aside-collapsed .aside-expand-btn svg { transition: transform var(--dur) ease; }
.workbench.aside-collapsed .aside-expand-btn:hover svg,
.workbench.aside-collapsed .aside-expand-btn:focus-visible svg { transform: translateX(2px); }
```

**交互细节**
- 热区 = 整条 44 × N（Q-C 直解：从 3.5% 覆盖提到 100%）。
- 悬停整条微亮（`--surface-2` = #F9FAFB 对 `--bg` #F3F4F6，是仓内既有悬停色阶，`--surface-3` 与 bg 同色故不可用）+ 图标右移 2px 作方向暗示。
- 焦点态：`outline: var(--focus-outline)` + `outline-offset: -2px`，否则满高按钮会画出一条越界的竖长矩形。
- 命中区无文本、拖拽选区风险为零；`title`/`aria-label` 沿用 app.js:9139-9140 回填的 `MSG.collapse_toggle`，`aria-expanded` 由 9147-9149 同步，**JS 零改动**。

**优点**：直解 Q-A/Q-C；新可点区比现状大一个数量级，钉 ①「折叠入口显眼」的立法本意被**更彻底**满足（现钉防的是「隐形」，本方案是「超显眼」）；零新增元素。
**缺点**：视觉体重由「按钮」变成「条」，若 owner 期待一个明确的「可点元件」，需要 hover 才认得出；常驻 affordance 仅剩一枚 17px 箭头。

### 乙案 · 端部箭头 + 竖线轨道（**次推**）

**形态**：展开钮从条**正中央移到把手条顶部**（端部），其下用一条 1px `--border` 竖线从钮底一直延伸到条底，构成「抽屉轨道 / 标尺」语汇。

```css
.workbench.aside-collapsed .aside { padding: var(--space-2) 0; justify-content: flex-start; }
/* 轨道 = aside 的伪元素（零新增 DOM 元素） */
.workbench.aside-collapsed .aside::after {
    content: "";
    width: 1px;
    align-self: center;
    flex: 1 1 auto;
    min-height: var(--space-4);
    margin-top: var(--space-2);
    background: var(--border);
    pointer-events: none;
}
```

**交互细节**
- 钮位置与把手条**端部**对齐（与 rail 顶部的品牌 mark、左栏导航首项形成同一「从上往下读」的起手式）；轨道在钮正下方续下。
- 悬停时轨道由 `--border` 提亮至 `--border-strong`（`transition: background var(--dur) ease`），箭头同步提色——**悬停反馈沿轨道传播**，比甲案的单块着色更有「这是一条可拉的东西」的实感。
- 可点区仍只有钮本身（900px²），**Q-C 未解**；若要一并解掉，可把钮也 `flex: 0 0 auto` + 轨道 `pointer-events: auto`（轨道可点），但伪元素不可聚焦，需另设命中层——**建议不做**。
- 零新增 DOM 元素；轨道纯 token 描边，零色值字面。

**优点**：Q-B（把手条语言）解得最干净；把手条从「空条」变成「有结构的轨道」，与 rail 的导航语汇同族；端部起手式符合阅读习惯。
**缺点**：Q-C 未解（owner 的「悬浮」体感只是从「条中央」挪到「条顶部」，没消失）；竖线在窄高窗口（<600px）下会退化成一根短棍。

### 丙案 · 分节线节拍器（**叠加增强，非独立方案**）

**形态**：把手条上画 N 段短横/竖刻线，每段对应右栏一张被折叠的卡（现状 4 张：运行控制 / 两阶段流水线 / 系统状态 + 卡内小节），把条子变成「折叠了多少内容」的**节拍器**。

```css
.workbench.aside-collapsed .aside::after {
    content: "";
    width: 1px;
    align-self: center;
    flex: 1 1 auto;
    background: repeating-linear-gradient(
        to bottom,
        var(--border) 0 1px,
        transparent 1px var(--space-3));
}
```

**交互细节**
- 刻线数**不与真实卡数联动**（CSS 静态渐变），属装饰性隐喻；增删右栏卡时需手改渐变参数 → **维护债**，须在实现卡注释里写死这条约定。
- 悬停时整条/整轨道提亮至 `--border-strong`（与乙案共用一条规则即可）。
- 建议**叠在甲或乙之上**（甲给热区、乙给轨道、丙给刻线），不单独成立。

**优点**：Q-B 之外的增量价值——用户能感知「里面不止一屏」，为「为什么值得展开」提供动机。
**缺点**：装饰与事实脱钩的风险；`repeating-linear-gradient` 虽全 token（零色值字面、零 gap 声明，不触三钉），但属本仓新语汇，需主审确认是否引入。

---

### 丁案 · 保留带框方钮、只改位置（**最小改动退路**）

**形态**：共规块一字不改，只把折叠态 `.aside-expand-btn` 从居中改为顶部对齐（或底部对齐），去掉 `.aside` 折叠态的 `justify-content: center`。

```css
.workbench.aside-collapsed .aside { justify-content: flex-start; }
```

- **优点**：改动面最小（1 行），钉 ① 的「带框 + surface 底」完整保留，**无任何钉冲突**。
- **缺点**：**Q-A 的「悬浮方钮」只换了位置，没换形态**——30×30 方钮在 44px 满高条里仍是孤岛；Q-C 未解；Q-B 未解。**仅作为主审否决甲/乙后的兜底**，不推荐。

## §3 展开态收起钮是否联动调整

**现状**：`absolute; top: var(--space-2); right: 20px`（481-486），右缘与首卡右缘齐平，`--surface` 不透明底用于**遮住首卡右上角被压住的描边**；图标 `panel-right-close`。

**硬约束**：钉 ①'（:5125-5128）把 `position: absolute` + `right: 20px` 钉死 → **位置零改动**。卡G1 执行记录遗留项 4 已把「贴边距离/是否改挂卡头行」列为待主审走查裁量 → 属后续卡，不在本件。

| 联动项 | 方案 | 判定 |
| --- | --- | --- |
| 位置 | 维持 `top: var(--space-2)` / `right: 20px` | **零改动**（被钉） |
| 边框/底色 | 维持 `1px solid var(--border)` + `--surface` | **零改动**（被钉，且遮盖功能真实需要） |
| 图标 | 保持 `panel-right-close`；备选换成 `chevron-left` 与折叠态构成「箭头对」 | **推荐保持现状**——复合图形「面板+分割线+左箭头」的语义比纯箭头强，且与 rail/console 既有图形语汇无冲突 |
| 可访问性 | 两钮共用 `MSG.collapse_toggle`「折叠/展开」（app.js:731 / 9139-9140）+ `aria-expanded` 同步（9142 / 9147-9149） | 可选增强：拆成两个 MSG 键（「展开右栏」/「收起右栏」）让读屏用户拿到方向化文案。**MSG 字典不在快照面，加键合法**，但属行为面，须另卡；本件仅记录 |

**「双态不对称」要不要抹平？——结论：不抹，且不对称是功能性的。**
展开态的钮**压在卡片之上**，必须用不透明 `--surface` 底遮住被压住的卡边描边；折叠态的钮**独占把手条**，背后无内容可遮，所以可以无框。把两者强行画成一样，反而要在折叠态给一个不需要遮盖的钮硬加一块不透明底，或在展开态让卡边从钮下透出来。**「展开态带框遮盖 / 折叠态无框独占」是一条自洽的规则，不是设计不一致。**

## §4 推荐项与理由

**推荐组合：甲案（主）+ 丙案（叠加刻线，条件性）+ 展开态零改动。**

1. **先解最痛的两条**：owner 的原话重心在「悬浮」「布局不合理」，而 Q-A（孤岛方钮）与 Q-C（3.5% 可点率）互为表里。甲案把按钮放大成把手条本体，一次解两条，且**不与任何既有钉冲突**（只加折叠态专属覆盖规则，共规块与两钮 class 属性一字不动）。
2. **钉的立法本意被更好满足**：钉 `test_realdevice_feedback_pins` ① 是为防「透明边 + bg 底 → 折叠入口隐形」而设。甲案在折叠态把入口放大到满条、箭头常驻、悬停整条着色，**隐形风险不增反降**；共规块的 `border`/`background` 声明保留不动，断言字符串仍在块内 → 钉保绿。
3. **乙案作为备选保留**：若主审/owner 真机判定「条中央空着没东西」比「悬浮方钮」更糟（即 Q-B 比 Q-A 更扎眼），切乙案；乙与甲**共用同一条折叠态覆盖骨架**（都只改 `.workbench.aside-collapsed` 作用域下的规则），二选一成本低。
4. **丙案条件性叠加**：只有在主审认为「条子太空」且接受装饰与卡数脱钩的维护债时才加；否则维持纯甲案。
5. **展开态一律零改动**：位置/边框/底色三处全被钉或被遮盖功能锁定，唯一开放项是图标二选一（非推荐改动）与 aria 文案拆分（另卡）。
6. **丁案只作兜底**：它换汤不换药，不解决 owner 提的任何一个核心点，除非前案全被否。

## §6 遗留问题 / 提请主审注意

1. **真机未验**：四案均为静态推演。「满高按钮的焦点环」「整条悬停着色在暗色主题（`style.dark.css` 仅覆盖 token 层）下的观感」「窄高窗口（<600px）下轨道/刻线的退化表现」三项须主审真机双态 + 三档缩放走查裁定。暗色主题因全走 token，理论上自动跟随，但 `--surface-2` 对 `--bg` 的明度差在暗色下是否仍可辨，需实测。
2. **满高按钮的语义节点面积**：`.aside-expand-btn` 仍是 `<button>`（零 id、零静态文案、`aria-label` 由 JS 回填、`aria-expanded` 已同步），但视觉/命中面积从 30×30 变成 44×N。屏幕阅读器与自动化测试（`data-testid="aside-expand-btn"` 黑盒锚点）不受影响；若有走查脚本按元素 bounding box 断言尺寸，需同步告知。
3. **热区扩大后的误触**：满条可点意味着**靠近把手条的任何一次落空点击都会展开右栏**（不再需要瞄准 30px 方块）。这通常是想要的（减少瞄准成本），但若主审在真机上感到误触，**丁案 + 乙案顶部对齐**是回退组合（热区回到 900px²）。
4. **两侧手的对称性**：左栏 rail（220px，窄窗 64px）在窄窗下与折叠把手（44px）形似，均为纯图标竖条。若折叠态把手改为刻线语言（丙案），左栏窄窗态的观感需一并复核，避免左右两条语汇打架。
5. **两钮文案同键**：`MSG.collapse_toggle`「折叠/展开」被两钮共用（app.js:731/9139-9140），读屏用户在两个状态听到同一句话。拆键属行为面，本件只记录不动。
6. **本件零代码**：本文件出现的所有新选择器（`.workbench.aside-collapsed .aside-expand-btn` 覆盖块、`.workbench.aside-collapsed .aside::after` 轨道/刻线）在仓内当前**零存在**；实现卡须同步补/调静态钉（尤其确认钉① 的两条 `in blk` 断言在共规块未被触碰的前提下仍绿）。
