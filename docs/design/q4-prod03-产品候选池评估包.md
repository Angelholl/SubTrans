## 3. 逐候选评估

### 3.1 引擎页 D 项重构 —— **专项评估**

- **内容**：把引擎页（`#tab-engine`「API 与模型选择」）从现有「阶段A/阶段B/兜底」多卡纵向堆叠骨架，改为**左侧列表＋右侧详情**（master-detail）信息架构。
- **价值**：D2026-0929-03 时代的动机是配置区视觉拥挤/层级不清。**关键事实：该动机的可见部分已被后续轮次消化**——d1013/d1014 十四卡（已落，roadmap:152）在既有堆叠骨架内解决了「框过长」（grow 无上限，折叠态地址框 ≈1300px）、「三列错落」（兜底容错卡标签线错位 ≈17px）、「5 控件无分组」三大痛点，方案根因分析与落地证据见 `docs/design/d1013-设计-引擎页布局优化方案.md` §1.3/§1.4/§6。D 项换骨架的**剩余增量价值 = 信息架构层收益**（引擎条目多时导航效率），当前引擎页仅 3 组配置，收益有限。
- **范围**：`index.html` #tab-engine 结构重排 + style.css + stage-group 守卫/契约钉全面解冻重钉（id 全集 223、i18n 键集 186、字号/gap/行高三白名单、钉①切片锚——d1013 §7 列出 8 条钉约束，换骨架全部要重核）。
- **依赖**：GUI 黑盒验证（web-gui-tester 范式）；无外部/数据依赖。
- **验收**：可写清（五 TAB 走查+钉重构全绿），但**前置验收不存在**：重启条件=真机走查暴露引擎页布局痛点，而 D2026-1022-01 四项真机验收（含 P1-4 引擎页）已通过、未报布局痛点。
- **资源**：粗估 4–8 人日（含钉解冻与全量回归），单执行者。
- **风险**：中高——钉体系在引擎页最密（d1013 §7 八条）；换骨架回归面大且与「测试基线只增不减」纪律摩擦；3.1 刚收口，再动引擎页有视觉回退风险。
- **优先级建议**：**低（维持挂起）**。依据：①重启条件未触发（最新真机验收无引擎页布局投诉）；②痛点大头已被十四卡消化；③钉解冻成本高。
- **结论建议**：~~继续观察~~ → **已关闭（2026-10-23 owner 终裁）**：owner 经 master-detail 渲染对比图后裁定不采纳，D 项关闭收口、不重议；roadmap 两处挂账行已同步回写。评估时点的「维持挂起」建议由此升格为终态。

### 3.2 多格式输出（保 ASS/VTT 输出侧扩展）—— **专项评估（新候选登记前）**

- **价值**：现状全链唯一输出口 = 手写 SRT（`subtransjav/refine/filters.py:56-63 build_srt`；终稿写点 `pipeline_v2.py:1607`，命名契约单点 `v2_outputs.py:194-204`），成品固定 `{stem}_final_cn.srt`。导入侧 ASS/VTT 经 pysubs2 转 SRT 时**样式不可逆丢弃**（`subtitle_convert.py:232-287`：override 标签/样式段/说话人名/逐字高亮全剥）。用户导入带样式字幕（卡拉OK、定位、双色对白）后翻译成品丢失全部样式；压制链靠 ffmpeg `force_style` 重新赋予统一样式（`hardsub.py:267-286`），无法还原原始排版。**保 ASS 输出能显著提升「样式保真」类用户的成品质量**，是导入侧多格式（已落）的自然对称缺口。
- **范围建议**（若立项再细化）：终稿出口新增 ASS（或 VTT）平行写出/可选写出；**不包含**——原始样式映射回译链（翻译文本如何嵌回原样式事件）、压制链样式透传，这两个是第二阶段议题。
- **依赖（技术取证，置信度高）**：pysubs2 已 pin `>=1.8,<1.9`（`pyproject.toml:46`，1.9+ 需 py≥3.12 冲突），**1.8 原生支持 ASS/VTT/SRT 双向导出，无新依赖**。TM 库纯文本对（`tm.py:7-16`），与输出格式**零耦合**。内部表示瓶颈：全管线 entries 结构 `{"index","timing","text"}`（timing 为字符串）贯穿，非 SRT 输出需在出口层转换而非贯穿改造——即**只在 v2_outputs/终稿写点加一层导出**，管线本体可不动。
- **验收线索**：现有钉面清单——`test_v2_outputs.py`（命名契约）、`test_subtitle_convert.py`、`test_hardsub_command.py`、`test_no_srt_dependency.py` 等；`final_suffix` 契约有单点注释「全仓终稿路径只许经本函数取后缀」，扩格式必经此点，验收锚清晰。缺：**用户级验收标准**（保真到什么程度算过——样式段原样保留？还是仅 event 级标签回嵌？）→ 信息缺口①。
- **资源**：粗估 5–10 人日（出口层导出+命名契约扩展+编码嗅探复用+测试钉扩展+GUI 输出选项），单执行者。
- **风险**：中——触碰命名契约单点（多文件成品件备份/清理表 `v2_outputs.py:177-229` 要联动）；编码（ASS 常见 UTF-8/带 BOM）；与「校对页仍仅 SRT 语法解析」的边界要写清（`api.py:4815-4849`）；发布面涉及成品件清单变化（release smoke 断言）。
- **优先级建议**：**高（建议立项评估）**。依据：①对称缺口明确、用户可感知；②零新依赖、TM 无耦合、改动可收在出口层；③验收锚（命名契约单点+现有钉）清晰。
- **结论建议**：**建议进入开发立项评估**。立项时须先补齐信息缺口①（样式保真口径）与 owner 需求信号确认（见 §7 待确认 1）。
- **注**：候选池登记动作（roadmap:226 新增条目）属立项批，本包不执行。
