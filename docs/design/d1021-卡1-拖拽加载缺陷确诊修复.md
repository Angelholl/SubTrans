## 执行记录（阶段2：确诊＋诊断埋点）

### 根因结论

真机未在本机复现（无 WebView2 可交互 GUI 环境；仓库 `Logs/gui.log` 9MB 全为
pytest 驱动的 INFO/ERROR 行，无 `dom_events_bound`/drop 线索，不能作为真机证据）。
改用「源码＋pywebview 6.2.1 安装源」逐环节对链取证，得两条确诊缺陷：

- **缺陷A（已修，阶段1）**：`review.js:128` `REVIEW_SRT_EXTS: ['.srt']` 与
  `main.py` 放行集不同步 → 校对页拖入 .ass/.ssa/.vtt 被 `isSrt` 静默丢弃。
  只影响 tab-review，不解释"整窗拖入都不加载"。
- **缺陷B（高置信，静态确诊，需裁决）**：`assets/app-file-list.js:63-69`
  `#fileList` 的 `drop` 监听里 `e.stopPropagation()` 直接掐断冒泡链：
  事件在 #fileList 处终止 → 永远到不了 `bind_dom_events` 注册的
  `document` 级 drop 监听 → pywebview `js/api.js:90-101` 的
  `chrome.webview.postMessageWithAdditionalObjects('FilesDropped')` 从不执行
  → Python 侧 `on_drop_event` **一次都不会被调用**（连日志都不进）。
  同文件 `dragover/dragenter` 亦 `stopPropagation`，故悬停高亮只在本元素内生效。
  该监听自身注释（L67-68）写着"路径提取由 main.py 经 pywebviewFullPath 完成"，
  与其 `stopPropagation` 自相矛盾——即历史遗留的"防浏览器打开文件"写法在
  pywebview DOM 桥接方案下反而吞掉了唯一入口。**用户把文件拖到文件列表卡片
  区域（含空列表区）＝完全无反应**，与真机"拖入无法加载"表征一致。
  修复需删 `app-file-list.js` 的 `e.stopPropagation()`（drop 保留
  `preventDefault`）——该文件在禁改清单内，**停在待裁决，未改**。

其余疑点排除/降级：

- 疑点1（绑定失败/异常）：`bind_dom_events` 的 `except` 只覆盖 Python 侧注册；
  `Element.on` 的 `@_exists` 会吞掉 JS 注入失败而不抛，故"打印了
  dom_events_bound"并不等于 JS 监听真的注入成功 → 已用 `_dnd_state`
  计数补上这一盲区（见埋点③）。
- 疑点2（private_mode + pywebviewFullPath）：无法本地证伪；已用
  `pathless` 计数区分（见自查步骤⑤）。
- 疑点3（`easy_drag: True`）：frameless=False 时 easy_drag 不参与拖动区，
  与页内 HTML5 drag 无冲突，降级为非疑点。
- 疑点4（document 级 dragover 未 preventDefault）：`DOMEventHandler(..., True, True)`
  第二参即 `prevent_default`，实际已 preventDefault；仅在缺陷B吞事件的区域失效
  （该区域自备 preventDefault，不会触发 WebView2 打开文件），故表现为静默无反应
  而非打开文件。

### 诊断埋点（纯增量 print，零行为分支改动）

`main.py on_drop_event`：

1. `[drop] event received files=N` —— 入口（**没这行＝事件没到 Python**，即缺陷B指纹）；
2. `[drop] filter pathless=X allowed=Y of N` —— 后缀过滤前后；`pathless>0`
   ＝ pywebviewFullPath 注入失效（疑点2），`pathless=0 且 allowed=0`＝后缀全拒；
3. `[drop] dnd_listeners=<n>` （`bind_dom_events` 内，读 pywebview
   `_dnd_state['num_listeners']`）—— 仅 JS 侧 drop 监听真正注入成功才 ≥1；
   =0 或 unavailable 即 pywebview DOM 桥接未生效（疑点1）；
4. `[drop] evaluate_js begin n=<k>` / `[drop] evaluate_js ok` —— 转 JS 前后
   （只有 begin 无 ok ＝ `ReviewUI.onDroppedFiles` 抛错/超时）。

### 真机自查步骤（复现时应看到什么）

1. 启动含本批埋点的包，`gui.log` 应出现 `dom_events_bound` 后紧跟
   `[drop] dnd_listeners=1`（≥1）。为 0/unavailable → pywebview DOM 绑定失效。
2. 把 .srt 拖到左栏虚线框「拖拽 .srt 字幕文件到这里」→ 期望恰好 4 行：
   `event received files=1` → `filter pathless=0 allowed=1 of 1` →
   `evaluate_js begin n=1` → `evaluate_js ok`，且文件进入列表。
3. 再把同一文件拖到下方文件列表卡片（含空列表）→ **若连第 1 行都没有**，
   即命中缺陷B（fileList stopPropagation 吞事件），可据此批准越界修复。
4. 若第 1 行有而 `pathless=N` 与 files 同数 → pywebviewFullPath 注入失效
   （private_mode/WebView2 组合，疑点2），此时不会出现 evaluate_js 行。
5. 若 `allowed=0` 而 `pathless=0` → 后缀不在白名单（检查文件名/大小写/是否
   浏览器改名，如 `x.ass.txt`）。
6. 校对页（tab-review）拖 .ass/.ssa/.vtt：阶段1 后应直接进 `setSrtPath`
   （不再静默丢弃）；若只加载视频不加载字幕，看是否走了 `allowed` 行。
