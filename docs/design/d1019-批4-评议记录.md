## 二、[HIGH_RISK_OBJECTION] 逐条回应

### HRO-1（驳回）「`app-modal.js:728` 裸调 `fmtGB` 是第二处行为翻转」

**评议员主张**：`fmtGB` 只在 `app-refine-asr.js` 声明；`app-modal.js:728` 裸调在现状会抛 `ReferenceError`，
升顶层后变成可用函数——所以行为翻转不止一处。

**主模型回应：驳回（事实判断不成立），但采纳其文档修正要求。**

证据（可复算）：

```
app-modal.js:603   models(opts) {                    ← 方法体起点（4 空格缩进）
app-modal.js:637   // fmtGB 本地版：模块级同名函数在 RefineUI IIFE 闭包内（:4730），
                   // AppModal 顶层对象不可见（黑盒抓缺陷：ReferenceError 中断面板渲染）
app-modal.js:639   const fmtGB = (n) => Math.round(n / 1073741824 * 10) / 10 + 'GB';   ← 局部声明
app-modal.js:728   fmtGB(entry.bytes)                ← 同一方法内 .forEach 回调，闭包解析到 :639
```

- :639 与 :728 同属 `models(opts)`（起于 :603）；:728 在外层方法内的回调里，按词法作用域绑定 :639 的局部常量。
- :637 的注释是该缺陷**曾经被黑盒抓到并已修**的留痕（"ReferenceError 中断面板渲染"），不是现症。
- 因此现状不抛错；升顶层后局部仍遮蔽全局，行为不变。

**同时采纳的部分**：勘探报告 §6.1 原文「其他文件对 172 个名字的真实代码引用 = 0」与 §6.2 列 `openDir` 自相矛盾，
已改为逐处表（全局引用 0、局部遮蔽 1、注释 6、字符串键 2、模板串误报若干），并加勘误段；
方案书 §2.1、拍板点 P4 同步加注。

### HRO-2（采纳）「172 个全局符号是永久性面扩张，owner 必须明示接受」

   替代物是「172 个精确名字集合钉」+ 逐文件 sha。

### HRO-3（部分采纳）「新钉不能自证去壳配方；报告 §二 配方与 `6051c666` 不符」

**采纳事实部分，驳回绝对化要求。**

- **采纳**：报告 §二 原代码块只删 3 行、不搬 L159，实算 `5fd2190e…`，与 `6051c666…` 不符——这是真笔误。
  已改为完整配方（删 3 + 搬 1），并保留 `5fd2190e…` 作对照，证明「搬 1 行确实改了字节」。
- **采纳**：在方案 §1.4 与卡面 A.2 增加**独立复算**步骤——从 `git show 1eb262c:…app-main.js` 重算配方，
  与 `read_all()` 实算比对，不依赖工作区产物。
- **驳回**：「测试必须自证配方」在原理上不可达——任何测试的期望值都可被同一提交同步修改；钉的定位是**变更探测器**，
  不是防篡改证明。当前组合（逐文件 sha + 载荷钉 + 独立复算 + 主审逐行 diff）已是本仓既有最高强度。
