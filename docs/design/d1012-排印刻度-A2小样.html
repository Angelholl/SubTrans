归位映射与 S6 判定

A档 A · 三档收敛
Tier 1 零复议 钉④ 四条核心值全维持；字重显式 400/700（渲染不变）
Tier 2 需 S6 22×11px、2×10px、5×12.5px 归位到 --font-xs/-sm
Tier 2 需 S6 页头 18px → 14/700（与区块标题同字级，靠颜色与留白区分）
不新增 无新 token，刻度即 handoff §5 既有三档
收益：刻度闭合、零新增、实现最简；
代价：页头与区块标题同为 14/700，层级只差颜色（text-1 vs text-2）与一条分隔线——若 owner 觉得"进页没大标题"，这档会显平。
B档 B · 新增 15px
Tier 1 零复议 同档 A（钉④ 核心值 + 字重显式化）
Tier 2 需 S6 同档 A（11/10/12.5px 归位）
Tier 3 需 S6 新增 --font-lg:15px，页头用 15/700
刻度扩一档 15 / 14 / 13 / 12 四档（注意：不触及钉④ 的三条字号 token 值，但属节奏扩档）
收益：页头有独立层级，"进页有大标题"，与 13/400 副标题拉得开；
代价：多一个 token 要长期维护，且与钉④"字号节奏禁区"立法意图最接近 → 必须走显式复议，不能顺手加。
design-expert 判定：推荐档 A。理由：① owner 痛点集中在"字太小、看不清"（P0-2 的 24 处低于 12px），不在"标题不够大"——先把 11px 抬到 12px 就能解决主诉，没必要为页头单开一档；② 档 A 让刻度完全闭合在 handoff §5 既有三档内，新增 token 数为 0，后续维护与静态钉实现都最简单；③ 字重只剩两档后，页头与区块标题同字级靠颜色区分是Notion/Vercel 系的常规做法（方向已锁的风格里本就不用超大标题），不违背 brief。
档 A 仍需一次 S6：因为 11px→12px、10px→12px、页头 18→14 都改变渲染结果（保守口径：改渲染即视为动节奏）。触发源 = owner 在《G 节痛点点选表》勾中的 P0-2 / P1-10。
若 owner 勾选"页头必须明显大于正文" → 改选档 B，并把 --font-lg:15px 写入归一提案 §4 的 Tier 3 表格后一并复议。
两者都不改变：钉④ 四条核心值、400/700 两档字重、12px 元信息下限。
