# 阶段 0a · 空态四态清单（首次进入 / 运行中 / 失败 / 暗色）

> 3.1 UI 重塑计划 · 阶段 0a 交付物之四。展开审计报告 **P1-9（空态/占位/JS 态零设计）**，逐页回答同一个问题：**这一态有没有被设计过？**
> 判定口径：**有** = 有专门的视觉与文案；**部分** = 有元素但依赖 JS 填充、或只覆盖一半；**无** = 落到裸控件/纯空白/无反馈。
> 为什么单独列：`file://` 走查（模拟 pywebview 桥未就绪、首帧未注入）暴露的问题**全部**落在这一类；即便真机上 JS 会填充，**首帧 / 加载中 / hook 失败**三态仍无人负责。

---

## 0. 结论先行

1. **7 页 × 4 态 = 28 格，只有 6 格判定为"有"**（翻译页空态、翻译页运行中 chip、校对页四态状态条、词库页空态引导、ASR 页失败诊断、控制台日志分色）；**13 格为"无"或"部分"**，集中在**质量页、高级页、ASR 词典页的空态**。
2. 根因是**结构性的**：大量控件采用"零 id / 零静态 i18n、文案由 JS 态 MSG 键填充"的省预算做法（`index.html:835-840`、`:1007-1019`、`:888` 等），**预算省下来了，但空/加载/失败三态没人写**。
3. **质量页是重灾区**：`<details>` 默认闭合（`index.html:605` 无 `open`）+ `.console-section{flex:1}`（`style.css:727-732`）双重作用 → 首屏两张卡各占半屏、第一张内容只有一行 summary，下方 380px 纯白空盒；"暂无导读数据"引导（`index.html:633`）**藏在闭合的 details 里永远看不见**。
4. **失败态是最缺的一态**：全站 `index.html` 只有 **1 处** `status-err`（`:579` 学习词库刷新）、**1 处** `hint-warn`（`:717` 默认隐藏）；右栏状态点虽在 CSS 里定义了 `.dot-err`（`style.css:1857`），但 `app.js:3603-3610` `setDot()` 只会切 `dot-running`/`dot-idle` → **永不变红**（P2-9）。
5. **暗色态是唯一整体健康的一态**：颜色全走 token，`style.dark.css` 覆盖后自动适配；例外只有 2 处组件内硬编码蓝阴影（`style.css:214/847`）与 `--cl-*` 日志五分色深浅共用（`style.css:57-62`）。

## 4. 结论与后续

1. **可直接复用的两个正面模板**：校对页四态状态条（`style.css:2186-2250`）、ASR 词典失败诊断（`style.css:1102-1179`）→ 阶段 2 的"空态/失败态"批以这两个为样式母版，不新发明。
2. **阶段 2 必开的独立批**（不混入常规视觉批）：
   - **质量页首屏治理**（P1-11）：`details` 默认态 + `.console-section` 撑高策略 + 空态引导前置；
   - **JS 态控件三态兜底**（P1-9）：每个"零静态文案"控件补 `空 / 加载中 / 失败` 三态，清单已由本文件 §2 列出；
   - **失败态锚点补齐**：把 `.status-err` / `.dot-err` 接进 `setDot()` 与各页状态 span（属行为变更 → `[HANDOFF_TO_CODING]`）。
3. **暗色专项**入阶段 4 验收：`style.css:214/847` 硬编码阴影 token 化 + `--cl-*` 深色覆盖评估。
4. 本清单不新增 owner 负担：需 owner 拍板的只有"哪些空态必须补设计"，已并入《G 节痛点点选表》各页"空态"栏。
