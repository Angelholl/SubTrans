## 根因（已实锤，勿再诊断，勿改此判定）

管线完成事件 `file` 字段是纯 basename（`subtransjav/refine/pipeline_v2.py:1107` `Path(path).name`；event_stream 以该 basename 作 files 键）。全链自动化 `_run_fullchain_automation` 用 `_resolve_guide_for_done_key`（`subtransjav/webview_gui/api.py:5767-5796`）解析导读路径，其 `directory = os.path.dirname(key) or "."`（api.py:5791）=进程 CWD，而导读 json 实落输出目录（out_dir=refine/pipeline_support.py:99-104：output_dir 未设=输入父目录）→ 找不到 →「诚实跳过」→ 0/0/0 done。真机证据 `Logs/gui.log:80200-80205`（16:53 一轮 3 秒收尾「跳过 …未找到导读 json（诚实跳过）」）。

## 改法

### A. 会话路径快照（仿 `_capture_session_stage_a` 同款范式，api.py:2524-2537）

- 新增 `_capture_session_paths(self, options)`：
  - `inputs`：`[str(p) for p in (options.get("inputs") or [])]`（原样全路径列表）；
  - `output_dir`：`str(options.get("output_dir") or "").strip()`；值为 `"source"` 或空 → 归一为 `""`（语义=随输入父目录，与 pipeline_support.py:99-104 同源）。
  - 存 `self._session_paths`（类级注解 `dict[str, Any]`，仿 `_session_stage_a` 的 mypy 落法）。
- `start_translation` 在 `self._capture_session_stage_a(options)`（api.py:1094）旁同点调用。
- `_init_translation_state` 中重置 `self._session_paths = {}`（防残留；确认该方法只在 start_translation 开头 api.py:1089 调用、钩子后不再跑，若不然即停卡说明）。

### B. `_resolve_guide_for_done_key` 多目录候选（api.py:5767-5796）

- 签名扩为 `_resolve_guide_for_done_key(self, done_key, session_paths=None)`（默认 None 兼容旧调用）。
- stem 推导逻辑不变（剥 .srt / `_final_` / strip_lang_suffix → `_preview_stem_candidates`）。
- 候选目录有序去重，**顺序硬约束**（评议员条件）：
  1. 会话输出目录（output_dir 非空时）；
  2. basename→会话 inputs 精确映射目录：inputs 中与 basename(key) 匹配（大小写不敏感）的唯一全路径之 dirname；非唯一 → 跳过此层；
  3. 其余会话 inputs 目录（去重，排除第 2 层已用）；
  4. key 自身 dirname 或 `"."`（最后，兼容旧口径与未来事件流改全路径）。
- 每个 候选目录 × stem candidate 试 `{cand}_质量报告导读.json`，返回首个存在且通过 stem 交叉校验者。
- **stem 交叉校验**（防同名误配兜底）：命中后 json 轻量读顶层 `stem` 字段（写入点 quality_report.py:1516），非空且 != 期望 stem → 视为未命中继续下一候选；字段缺失（旧数据）→ 放行；json 读失败 → 视为未命中。

### C. 逐文件 notices 落 last_run（可见性载体，评议员 HRO 修正要求）

- run dict 初始化（api.py:6064-6068 附近）增 `"notices": []`。
- 新增 helper `_fullchain_notice(self, run, text)`：调既有 `_automation_notice(text)`（gui.log+队列通道零变化）并 `run["notices"].append(text[:200])`，上限 50 条，超出丢弃且 `notices_truncated` 计数+1。
- 以下 notice 点改走 helper：跳过导读未找到（:6120-6121）、导读校验失败（:6127-6129）、无可自动修复（:6143-6144）、复验跳过（:6214-6216 附近）、收尾 done_note（:6222 附近）；provider 门 skipped 路径（:6088-6089）将 skip_reason 同步 append 进 notices。
- `_fullchain_write_last_run` docstring 补 `notices`/`notices_truncated` 字段语义（序列化零改动，dict 原样写）。
